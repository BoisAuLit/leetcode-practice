# finish-note：把复习笔记编入错题模式档案

仓库根目录：`/Users/bohaoli/Desktop/tuto/tuto_leetcode/leetcode-practice`。

## 输入格式

参数是一行，用 ` ::: ` 分隔三段：
```
<题目文件夹绝对路径> ::: <g|y|r> ::: <用户写的笔记>
```
没有参数时，只打印这段"输入格式"说明然后结束，不要改任何文件。

## 前提（已经由脚本做完，不要重复）

- `metadata.json` 的 `practice[]` 已经追加了今天这条记录，笔记原文已在这条记录的 `sticking_point` 里。**不要动 metadata.json。**（metadata 里只有 id / path / difficulty / link / practice，没有标题、没有信号→模式、没有守卫。）
- 笔记原文已经追加进该题的 `note.md`（和 solution.py 同级，`### 💬 日期 - finish 🟢`）；`solution_retry.py` 里带注释的 class 也已存进 `note.md`（`### 📝 日期 - retry N`）。**不要再往 note.md 写，也不要动它。** 读它可以，里面的历史 retry 记录能帮你判断这个错是不是复发。
- 软链接和 `solution_retry.py` 已经清理。

## 步骤

1. 读四样东西：`MISTAKES.md`（全文）、该题的 `metadata.json`（只拿 id；标题和信号→模式都在文件夹名里，直接看路径最后一段）、该题的 `solution.py`（理解笔记在说哪段代码）、该题的 `note.md`（有的话；里面最新的 retry 代码块就是用户这次写的、带注释的版本）。
2. 判断笔记属于哪一类：
   - **是一个 bug / 卡点 / 坏习惯**（例如"边界处又错了"、"忘了 sort 就剪枝"）→ 走第 3 步。
   - **只是心得、没有错误**（例如"carry 设成 1 很对"、"这题很无脑"）→ MISTAKES.md 是错题档案，不收心得。什么都不改，汇报"这是心得不是错误，脚本已记进 note.md"，结束。
3. 归档到 MISTAKES.md，**先问"属于哪个已有模式"**：
   - 属于已有模式 Mx → 该模式标题里的 **复发：n** 改成 n+1；在 **案例** 下追加一行 `- <题号> <标题> — <一句话说明错在哪>`（题号用 metadata 的 id，如 `0155`/`NC`）；如果笔记里有具体反例，追加到该模式的 **守卫反例**。复发达到 2 → 标题加 `⚠️ 已晋升清单`，并在顶部"提交前自检清单"加一条对应的勾选项（一行，和现有条目同样的语气）。
   - 不属于任何已有模式 → 新建 `## 模式 M<最大编号+1> — <名字>（复发：1）`，按现有模式的四段格式写：**触发场景** / **案例** / **守卫反例**（没有就写"待补"）/ **预防一句话**。
   - 无论哪种，更新底部"复发统计"表格里对应的行（新模式加一行，状态"观察中"；零成本检查项可直接 ✅）。
4. 不要改动与本次笔记无关的任何段落；保持文件现有的语气和格式（中文、加粗小标题、一句话预防）。
5. 最后用三行以内汇报：归入了哪个模式（或新建了哪个）、复发次数现在是多少、有没有晋升清单。守卫反例只住在 `MISTAKES.md` 对应模式的 **守卫反例** 下（第 3 步已写），不要建议往 metadata 里写。

## 不要做的事

- 不要改 `metadata.json`、`solution.py`、`note.md`，不要碰 `Today/`。
- 不要把同一条笔记同时记进两个模式；拿不准就选触发场景最贴的那个，并在案例行里说明。
- 不要重写或"润色"已有模式的描述。
