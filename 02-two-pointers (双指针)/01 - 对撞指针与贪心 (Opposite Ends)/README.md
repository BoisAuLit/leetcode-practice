# 01 - 对撞指针与贪心 (Opposite Ends)

## 算法定义

两个指针从序列的**两端向中间**走，每一轮根据当前这一对元素做出决策，并**永久丢弃**其中一侧的一个候选。
序列必须**有序**（或具备某种单调结构），否则「丢弃」没有依据。

## Pointer Movement Rules

| 题型 | 移动哪一侧 | 依据 |
|---|---|---|
| 和与 target 比较（0167、0633）| 和偏小移左、偏大移右 | 有序 ⇒ 另一侧已到极限 |
| 面积 / 容量（0011）| 移**较短**的那一侧 | 移长的一侧宽度变小而高度仍受短边限制，不可能更优 |
| 容量配对（0881）| 右端必动，左端能配则动 | 最重的人必须占一条船 |
| 接水（0042）| 移**较矮**的那一侧 | 矮侧的瓶颈已确定，可当场结算 |

## Loop Invariants

1. `[l, r]` 始终是「还没被排除的候选区间」。
2. 所有 `< l` 和 `> r` 的位置都已被证明不可能出现在最优解里（或已结算完毕）。
3. 每轮至少一个指针移动 ⇒ 最多 n 轮 ⇒ O(n)。

## 必备模板

```python
l, r = 0, len(a) - 1
while l < r:                      # ! 要不要取等看题意：0881 需要 l <= r
    # 1) 用 a[l] 和 a[r] 算出当前候选的值或判断
    # 2) 根据「哪一侧已经到极限」决定移动谁
    if cond(a[l], a[r]):
        l += 1
    else:
        r -= 1
```

## 最容易出错的地方

- **忘了「有序」这个前提**。无序数组上对撞指针没有正确性（LC-0001 就必须用哈希表）。
- **移动规则反了**。0011 移长边、0042 移高边都会得到错误答案，而小数据常常看不出来。
- `l < r` 还是 `l <= r`：求一对元素时用 `<`；像 0881 那样「剩一个也要处理」就得用 `<=`。
- 0977 正着填结果数组会覆盖还没读的数据，必须从末尾往前填。

## 与相邻家族的区别

- **Level 02 K-Sum**：在对撞指针外面套一两层固定元素的循环，核心还是本家族。
- **Level 03 同向读写**：两个指针**同向**，一个读一个写，不做「排除」而做「搬运」。
- **Level 06 快慢指针**：同向但**不同速**，用来发现结构（环、中点），不是缩小搜索空间。
