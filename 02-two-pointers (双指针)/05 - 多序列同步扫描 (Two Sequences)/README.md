# 05 - 多序列同步扫描 (Two Sequences)

## 算法定义

两个指针分别在**两个序列**上。每轮比较各自当前的元素，然后**只推进其中一个**（或两个一起）。
推进规则由题意决定，这是本家族唯一需要想清楚的事。

## Pointer Movement Rules

| 子类 | 推进谁 | 依据 |
|---|---|---|
| 子序列匹配（0392）| 匹配成功才推进短串指针，长串指针每轮必进 | 贪心：最早匹配不会更差 |
| 倒序 + 跳过（0844）| 各自跳过被删掉的字符后再比较 | 删除只影响左边 ⇒ 必须倒着扫 |
| 归并（1768）| 严格轮流 | 题意 |
| 区间交集（0986）| 丢掉**右端点更小**的那个区间 | 它不可能再和对面后面的区间相交 |
| 贪心配对（0455）| 配对成功双双前进，否则推进供给一侧 | 交换论证 |
| 分段比较（0165）| 各自吃掉一整段再比较，短的一边补 0 | 按段、按数值比较 |

## Loop Invariants

1. 两个指针各自指向「本序列里还没处理的第一个元素（或段）」。
2. 已处理的两段前缀之间的关系已经确定（已匹配 / 已输出 / 已判等）。
3. 每轮至少推进一个指针 ⇒ O(n + m)。

## 必备模板

```python
# 通用骨架
i = j = 0
while i < len(a) and j < len(b):
    if   cond_a(a[i], b[j]): i += 1
    elif cond_b(a[i], b[j]): j += 1
    else:                    i += 1; j += 1
# 收尾：按题意处理剩下的一截（0392 看短串有没有走完，1768 要把剩余拼上）

# 子序列匹配（LC-0392）两行版
it = iter(t)
return all(ch in it for ch in s)        # ! in 作用在迭代器上会消耗它，这正是贪心

# 区间交集（LC-0986）
lo, hi = max(a1, b1), min(a2, b2)
if lo <= hi: res.append([lo, hi])
if a2 < b2: i += 1
else:       j += 1
```

## 最容易出错的地方

- **0392** 的 `all(ch in it for ch in s)` 换成 `in t` 就完全错了 —— 靠的是迭代器被消耗。
- **0844** 的内层必须是 while（`"a##"` 会连续欠两次债），比较前要确认两个下标都 >= 0。
- **0986** 判空用 `<=`（闭区间）；推进时比的是**右端点**，相等时只能推进一个。
- **0151** 不要声称 O(1) 空间：Python 的 `str` 不可变，必须新建列表或字符串；
  真正的 O(1) 只存在于 C++/Java 的可变 `char[]` 上。
- **0165** 不能按字符串比大小（`"10" < "9"` 字典序成立但数值不成立），也不能按长度判大小
  （`"1.0"` 和 `"1"` 相等）。

## 与相邻家族的区别

- **Level 01 / 03**：两个指针在同一个序列上；本家族跨两个序列。
- **Level 06 快慢指针**：同一序列、不同速度。
- **归并排序的 merge**：0986 / 1768 的形状和它一样，但决策规则不同
  （merge 是「取较小的」，交集是「算交集再丢右端更小的」）。
