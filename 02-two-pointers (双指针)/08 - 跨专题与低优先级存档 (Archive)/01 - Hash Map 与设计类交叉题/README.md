# 01 - Hash Map 与设计类交叉题

本目录题目：**LC-0170 - Two Sum III - Data structure design**（P2）。

## 跨专题索引：LC-0001 Two Sum（P0）

它曾经在本专题的 `k-sum/two-sum/` 下，现已按主算法归属迁到：
[01-arrays-hashing/01 - Hash Set 与 Hash Map 基础/01 - LC-0001 - Two Sum](../../../01-arrays-hashing%20%28%E6%95%B0%E7%BB%84%E3%80%81%E5%93%88%E5%B8%8C%E8%A1%A8%29/01%20-%20Hash%20Set%20%E4%B8%8E%20Hash%20Map%20%E5%9F%BA%E7%A1%80/01%20-%20LC-0001%20-%20Two%20Sum)

**为什么不属于双指针**：LC-0001 的输入**无序**，最优解是「边扫边查补数」的哈希表 O(n)。
排序后再对撞是 O(n log n)，而且排序会打乱下标 —— 而这题要返回下标。
真正属于双指针的是 **LC-0167**（输入已排序、返回下标），它在
[本专题 Level 01/01](../../../02-two-pointers%20%28%E5%8F%8C%E6%8C%87%E9%92%88%29/01%20-%20%E5%AF%B9%E6%92%9E%E6%8C%87%E9%92%88%E4%B8%8E%E8%B4%AA%E5%BF%83%20%28Opposite%20Ends%29/01%20-%20%E7%BB%8F%E5%85%B8%E5%AF%B9%E6%92%9E%E4%B8%8E%E8%B4%AA%E5%BF%83%E5%86%B3%E7%AD%96/01%20-%20LC-0167%20-%20Two%20Sum%20II%20-%20Input%20Array%20Is%20Sorted)。

这组对比本身就是考点：**「有序」是对撞指针成立的前提**，没有它就退回哈希表。

## LC-0170 为什么是 P2

它考的是「插入频繁还是查询频繁」的设计权衡（哈希计数 O(1) 插入 / O(n) 查询，
或者维护有序列表 O(n) 插入 / O(n) 查询），双指针只是其中一种实现细节。
属于设计题，不属于双指针必刷模板。
