## 一、双指针到底是什么

「双指针」不是一个算法，而是**一类把 O(n²) 的二重枚举压成 O(n) 的论证方式**。能压下来的唯一理由是：**每一轮都能证明某一侧的某个候选不可能是答案，于是永久丢弃它。**

所以用双指针之前只要回答一个问题：**我凭什么敢丢掉这一侧？** 答案通常是下面六种之一 ——这正好就是六个算法家族。

| 家族 | 指针怎么走 | 凭什么能丢 | 基本不变量 |
|---|---|---|---|
| **01 对撞指针** | 两端相向，同速 | 序列**有序** ⇒ 这一侧已到极限 | `[l, r]` 是尚未排除的候选区间 |
| **02 K-Sum** | 外层固定 + 内层对撞 | 同上，外加排序后相同值相邻 ⇒ 可去重 | 已输出的组合互不相同 |
| **03 同向读写** | 同向，同速，一读一写 | `write <= read` ⇒ 不会覆盖未读数据 | `nums[0:write]` 永远是合法答案 |
| **04 回文** | 相向收缩 或 从中心外扩 | 回文的**对称性** | 已比较的两段互为镜像 |
| **05 多序列** | 两个序列各一个指针 | 各自有序 ⇒ 落后的那个不可能再匹配 | 两段已处理前缀的关系已确定 |
| **06 快慢指针** | 同向，**不同速**或固定间距 | 差值每轮变化恰好 1 ⇒ 必然相遇 | 环检测：差值模环长每轮减 1 |

第 07 家族（高阶字典序）是第 01 家族的推广：比较的单位从「元素」变成「后缀」，一次比较淘汰一整段起点。第 08 是存档，不参与主线。

## 五、Two Pointers vs Sliding Window（最容易混的一对）

两者都是「同向的两个指针」，区别在**谁驱动指针移动**：

| | Two Pointers（本专题 03 家族）| Sliding Window（`03-sliding-window` 专题）|
|---|---|---|
| 两个指针的含义 | `read` 遍历、`write` 是输出位置 | `left` / `right` 共同框出一个**窗口** |
| 谁决定移动 | `read` 无条件前进，`write` 只在满足条件时前进 | `right` 扩张直到窗口**违反约束**，然后 `left` 收缩直到合法 |
| 关心什么 | 前缀 `[0, write)` 的内容 | 窗口 `[left, right]` 的某个聚合量（和、长度、计数）|
| 典型问法 | 原地删除 / 搬移 / 分区 | 最长 / 最短 / 恰好满足某条件的连续子数组 |
| 判断口诀 | 「我要**改数组**」 | 「我要**一段连续区间**，且区间合法性随长度单调」 |

例子：**LC-1695 Maximum Erasure Value** 看起来是双指针，但它要的是「元素互不相同的最长子数组和」，约束随窗口变长而单调变差 ⇒ 滑动窗口。它被放在本专题的 [08 存档](08%20-%20%E8%B7%A8%E4%B8%93%E9%A2%98%E4%B8%8E%E4%BD%8E%E4%BC%98%E5%85%88%E7%BA%A7%E5%AD%98%E6%A1%A3%20%28Archive%29/README.md) 里，就是为了提醒这个区别。

## 六、一个模板怎么长出一堆变体

```
            while l < r:  根据「哪一侧到极限」移动一侧
                   │
    ┌──────────────┼──────────────┬──────────────┐
  和与 target     面积/容量      对称比较       外层套循环
  0167 0633       0011 0042      0125 0680      0015 0016 0018
                     │                              │
                  配对贪心                      批量计数
                  0881                          0259 0611
```

迁移的方法只有一条：**先写出不变量，再问「这一题的不变量改了哪一个字」**。
例如 0011 → 0042：不变量从「`[l,r]` 是候选区间」变成「`left_max` 是 l 左边的最高墙」，
移动规则就从「移短边」变成「移矮侧并当场结算」。两道题的代码骨架一模一样。
