# 05 - 单调队列与窗口极值 (Monotonic Deque)

## 核心定义

窗口的「和」「计数」可以 O(1) 增量维护，但**极值不行** ——
移除当前最大值之后，新的最大值是谁？没有办法从一个标量里恢复。
解决办法是额外维护一个 **Monotonic Deque（单调双端队列）**，
里面保存「未来还可能成为极值的候选」的**下标**。

## 决定性观察

1. **淘汰规则**：新元素 x 进来时，队尾所有 `<= x` 的元素（求最大值时）可以直接丢 ——
   它们**比 x 小、又比 x 先离开窗口**，在任何未来的窗口里都不可能是最大值。
   这条「更年轻且更优 ⇒ 老的永远出局」的论证是整个数据结构的灵魂。
2. **存下标不存值**：只有下标才能判断元素有没有离开窗口。
3. 每个下标最多入队一次、出队一次 ⇒ 尽管有内层 while，总复杂度仍是 **O(n)**（摊还）。

## Loop Invariant

队列里的下标严格递增；对应的值单调不增（最大值队列）或单调不减（最小值队列）；
队首下标始终在当前窗口内。因此**队首就是当前窗口的极值**。

## Window Expansion / Shrinking Rule

- **入队前**：从队尾弹掉所有不如新元素的候选。
- **取答案前**：从队首弹掉所有已经离开窗口的下标。

## Python 模板

```python
from collections import deque
dq = deque()                       # 存下标，对应值单调不增 → 队首是最大值
for right, x in enumerate(nums):
    while dq and nums[dq[-1]] <= x:
        dq.pop()                   # ! 队尾：更小又更老，永远出局
    dq.append(right)
    if dq[0] <= right - k:         # ! 队首：已经离开窗口
        dq.popleft()
    if right >= k - 1:
        ans.append(nums[dq[0]])    # 队首即窗口最大值
```

## 常见错误与边界

- 队列里存值而不是下标 ⇒ 无法判断元素是否已离开窗口。
- 忘了弹队首（过期下标），答案会取到窗口外的元素。
- 1438 收缩时两个队列的队首都要检查。
- 以为有内层 while 就是 O(nk)：**摊还分析**下每个下标只进出一次，是 O(n)。
- 把单调队列和普通的「频率表窗口」混为一谈 —— 它是一个独立的数据结构技巧。
