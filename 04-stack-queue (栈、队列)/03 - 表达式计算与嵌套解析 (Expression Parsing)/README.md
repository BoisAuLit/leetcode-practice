# Level 1 · 03 表达式计算与嵌套解析 (Expression Parsing)

## 核心定义
用栈保存「**外层还没算完的上下文**」，遇到进入嵌套就压栈，遇到退出嵌套就弹栈恢复。
这是栈最贴近「调用栈」本义的一类应用。

## 决定性观察
1. **后缀（RPN）不需要优先级**：操作数入栈，遇到运算符取两个出来算 —— 优先级已经写死在顺序里。
2. **中缀需要优先级**：加减要「延迟」，乘除要「立刻」。
   技巧：把 `a - b` 看成 `a + (-b)`，栈里只存**待相加的项**，最后一次性求和。
3. **括号 = 保存并恢复整个计算上下文**：进 `(` 时把「外层已算的结果 + 当前符号」压栈，
   出 `)` 时弹出来和内层结果合并。

## Loop Invariant
- LC-0150：栈里是「还没被任何运算符消耗掉」的操作数。
- LC-0227：栈里是「所有待相加的项」，乘除已经就地结算完毕。
- LC-0224：栈里是「每一层括号外侧的 (已累计结果, 进入括号时的符号)」。
- LC-0394：栈里是「每一层 `[` 外侧的 (已构造字符串, 重复次数)」。

## 模板
```python
# RPN
for t in tokens:
    if t in "+-*/":
        b, a = stack.pop(), stack.pop()
        stack.append(apply(a, t, b))      # 注意 a 在前、b 在后
    else:
        stack.append(int(t))

# 嵌套：进括号保存上下文，出括号恢复
for c in s:
    if c == '[':
        stack.append((cur_str, cur_num)); cur_str, cur_num = "", 0
    elif c == ']':
        prev, k = stack.pop(); cur_str = prev + cur_str * k
```

| 03/02 | LC-0341 Flatten Nested List Iterator | P1 | 迭代器契约：`hasNext` 必须把结构推进到下一个整数 |

## LC-0227 vs LC-0224（最常见的误解）
**它们不是「同一份代码加一个括号判断」。**

| | LC-0227 | LC-0224 |
|---|---|---|
| 运算符 | `+ - * /` | 只有 `+ -` |
| 括号 | **没有** | 有，任意层嵌套 |
| 难点 | **优先级**：乘除要立刻结算 | **上下文保存**：进括号要存外层结果和符号 |
| 栈里存什么 | 待相加的项（数字） | `(外层结果, 外层符号)` |

把两者硬合成一份代码（Basic Calculator III，LC-0772）是可以的，但那是第三道题，
需要同时处理优先级和括号，难度明显更高。先分别掌握这两个独立维度。

## Python 整数除法的坑（LC-0150）
```python
int(a / b)        # 向零截断 ✓ 符合题目要求：-7 // 2 应为 -3
a // b            # 向下取整 ✗ -7 // 2 == -4
```
必须用 `int(a / b)` 或 `-(-a // b) if (a < 0) != (b < 0) else a // b`。

## LC-0341 的迭代器契约
Lazy 写法下，**`hasNext()` 必须有副作用**：把栈顶的嵌套列表一路展开，
直到栈顶是一个整数（或栈空）。`next()` 只负责取走。
如果只在 `next()` 里展开，连续调用两次 `hasNext()` 就会返回错误结果。

## 常见错误
- LC-0150 的减法 / 除法操作数**顺序写反**。
- LC-0150 用 `//` 处理负数。
- LC-0227 忘了循环结束后还要结算最后一个数字。
- LC-0394 把多位数字当成一位（`"100[a]"`）。
- LC-0341 把展开逻辑放在 `next()` 里。
