## 这个 Pattern 是什么

本专题 Level 1 `03` 里其他题的 `feasible(x)` 都是一个**贪心模拟**
（Koko 数小时、1011 数天数、1552 贪心放球）。
还有一类重要变体：**`feasible(x)` 是一个计数函数**。

```
在值域 [min, max] 上二分 x
count(x) = 有多少个元素 <= x          ← 随 x 单调不减
找最小的 x 使 count(x) >= k           ← First True
```

**「第 k 小 / 第 k 大 / 中位数」几乎都能这么做。**

### 为什么答案一定是真实存在的元素（通用保证，必须会证）
设 x₀ 是最小的满足 `count(x₀) >= k` 的值。
若 x₀ 不在集合中，则 `count(x₀ - 1) == count(x₀) >= k`，
与 x₀ 的最小性矛盾。所以 **x₀ 必然是集合里真实存在的元素**。∎

这条论证让我们可以**在连续的值域上二分**，却保证得到一个真实元素。

## 代表题：LC-0378 Kth Smallest Element in a Sorted Matrix

**实体目录** → [`09-heap (堆)/top-k (Top K)/LC-0378`](<../../../09-heap (堆)/02 - K-way Merge 与候选扩展/01 - 多路有序序列合并/01 - LC-0378 - Kth Smallest Element in a Sorted Matrix>)

那里的 solution.py 包含四种解法：
用户原有的「全遍历 + 大小 k 的最大堆」、**值域二分 + 阶梯计数**、多路归并堆、以及暴力基准。

### 和 LC-0074 的重要对比
**LC-0378 不能用 LC-0074 的「展开成一维数组」**：
- LC-0074 保证「上一行末 < 下一行首」⟹ 整体有序 ⟹ 可以展开。
- LC-0378 只保证「每行递增、每列递增」⟹ 拼起来**不是**有序数组。

所以 0378 只能在**值域**上二分，不能在**下标**上二分。这个区别值得单独记。

### `count(x)` 怎么 O(n) 算（阶梯法）
从**左下角**出发（`row = n-1, col = 0`）：
- `matrix[row][col] <= x` ⟹ 这一列从上到下到 row 全都 <= x，累加 `row+1`，`col += 1`。
- 否则 `row -= 1`。
每步要么右移要么上移，总共最多 2n 步 ⟹ O(n)。

整体复杂度 **O(n · log(max - min))**。
