# Level 1 · 03 二分答案与可行性判断 (Binary Search on Answer)

> 本专题最重要的进阶家族。核心思想只有一句：
> **把「求最优值」变成「给定一个值，判断可不可行」。**

## 核心定义
Optimization Problem（优化问题）→ Decision Problem（判定问题）。
定义 `feasible(x) -> bool`，证明它单调，然后二分找边界。

## 三件套（每道题都先把这三件事写下来）

1. **答案空间 `[lo, hi]`** —— 上下界必须是「一定不可行」和「一定可行」的两端。
2. **`feasible(x)`** —— 通常是一次 O(n) 的贪心模拟或计数。
3. **单调性证明** —— 这一步**不能跳过**，它决定了二分是否合法。

## Minimize Maximum vs Maximize Minimum（必须分清）

| | Minimize Maximum | Maximize Minimum |
|---|---|---|
| 典型问法 | 「最小化最大的那个」 | 「最大化最小的那个」 |
| x 变大时 | 更容易可行 | **更难**可行 |
| 谓词形状 | `F F F T T T` | `T T T F F F` |
| 二分目标 | **First True** | **Last True** |
| 可行时更新 | `hi = mid` | `lo = mid` |
| mid 取整 | `(lo+hi)//2` 向下 | `(lo+hi+1)//2` **向上** |
| 例题 | 875、1011、1482、1283、410、378 | **1552** |

**Last True 的死循环陷阱**：更新 `lo = mid` 时若 mid 向下取整，
`hi == lo + 1` 时 `mid == lo`，`lo = mid` 原地踏步 ⟹ 死循环。
口诀：**更新哪一边，mid 就往哪一边偏。**
（或者用「闭区间 + 显式 ans 变量」的写法，彻底绕开这个坑。）

## 这一章的题，feasible 只有三种形态

| 形态 | feasible 在做什么 | 题目 |
|---|---|---|
| **累加取整** | `sum(ceil(x_i / d)) <= 限额` | LC-0875、LC-1283 |
| **顺序贪心分段** | 从左到右装，装不下就开新段，数段数 | LC-1011、LC-0410、LC-1482 |
| **排序后贪心配对 / 放置** | 排序 → 贪心选不重叠的配对或位置 | LC-2616、LC-1552 |
| **计数** | 数「<= x 的元素有几个」 | LC-0378 |

看出来了吗 —— **875 和 1283 的 feasible 在数学上完全一样**，
**1011 和 410 本质是同一道题**（天数=段数，容量=limit）。
这一章只有 4 个真正不同的 feasible，不是 8 个模板。

## 各题要点

| # | 题 | 优先级 | feasible 是什么 | 单调性的关键前提 |
|---|---|---|---|---|
| 01/01 | LC-0875 Koko Eating Bananas | P0 | `sum(ceil(pile/speed)) <= h` | 速度越大用时越短 |
| 01/02 | LC-1011 Ship Within D Days | P0 | 顺序贪心装船数天数 | **包裹顺序固定**，否则是装箱问题 |
| 01/03 | LC-1482 m Bouquets | P0 | 数连续已开花段能切几束 | 天数越大开的花越多；**先判 `m*k > n`** |
| 01/04 | LC-1283 Smallest Divisor | P1 | `sum(ceil(x/d)) <= threshold` | 除数越大和越小 |
| 02/01 | LC-0410 Split Array Largest Sum | P1 | 顺序贪心分段数段数 | **元素非负**，否则「超过就断」失效 |
| 02/02 | LC-2616 Minimize Max Diff of Pairs | P1 | 排序后贪心选相邻不重叠配对 | 排序后只需考虑相邻配对 |
| 03/01 | LC-1552 Magnetic Force | P1 | 排序后贪心放球 | **Last True**，mid 要向上取整 |
| 04/01 | LC-0378 Kth Smallest in Sorted Matrix | P1 | 阶梯法数 `<= x` 的个数 | 计数随 x 单调不减 |

## 向上取整的正确写法
```python
(x + d - 1) // d      # ✓ 纯整数运算
-(-x // d)            # ✓ 等价
math.ceil(x / d)      # ✗ 大整数时浮点掉精度
```

## 为什么顺序贪心分段是最优的（LC-1011 / LC-0410 共用）
要判断「能否用 ≤ k 段」，段数越少越好。
「当前段装得下就不开新段」不会更差 —— 提前开新段只会让当前段留空、总段数不减。
所以贪心得到的段数就是所有合法分法中的**最小**段数。
**前提是元素非负**：若有负数，加一个元素可能让段和变小，「超过 limit 就断开」立刻失效。

## 为什么最小可行的 x 就是答案
`feasible(x)` 为真 ⟺ 存在一种方案，其代价不超过 x。
设最优代价为 OPT，则 `feasible(OPT)` 为真，而任何 `x < OPT` 都不可行。
所以「最小的可行 x」= OPT。∎

## 复杂度：别写成 O(log R)
**`O(n · log R)`** —— R 是答案空间的宽度，每次 feasible 都要扫一遍数据。
LC-1552、LC-2616 还要先排序，是 `O(n log n + n log R)`。

## 什么时候**不能**用二分答案
- feasible **不单调**（目标函数不是单峰、或资源互相挤占导致 x 变大反而不可行）。
- feasible 本身无法在多项式时间内判定。
- 答案空间不是可枚举的离散区间（连续实数要改成「二分到精度 eps」）。

**绝不能因为题目在问「最小的 X」就条件反射地二分。** 先证明单调性。

## 常见错误
- LC-1482 忘了先判 `m * k > n` ⟹ 在空可行域上二分，返回错误答案。
- LC-1552 用了向下取整的 mid ⟹ 死循环。
- LC-0410 在含负数的数组上套贪心分段。
- 把 Minimize Maximum 的边界更新直接搬到 Maximize Minimum。
- 用 `math.ceil(x / d)` 处理大整数。
- 复杂度说成 O(log R)，漏掉 feasible 的 O(n)。

## 复习时的 Pattern Recognition
> 「最小化最大值」「最大化最小值」「最少需要多少 X 才能…」
> 「在 D 天内 / H 小时内完成」「第 k 小」
> → 先写三件套：答案空间、feasible、**单调性证明**。
