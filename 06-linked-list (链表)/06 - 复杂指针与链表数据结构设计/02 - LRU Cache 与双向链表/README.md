## 为什么它仍然属于链表专题的知识地图

LRU 是**链表结构**最重要的应用：它回答了一个纯粹的链表问题 ——
**「怎样 O(1) 地把任意一个节点挪到链表头部？」**

## 决定性观察（本章真正要掌握的）

### 为什么必须是**双向**链表
- Hash Map 给了我们 O(1) **拿到那个节点**的能力。
- 但要把它从链表里摘下来，需要它的**前驱**。
- **单向链表拿不到前驱**（只能从头扫，O(n)）。
- **双向链表的节点自己记着 `prev`** ⟹ 摘除就是两行，O(1)：

```python
node.prev.next = node.next
node.next.prev = node.prev
```

**这就是整道题选择双向链表的全部理由。**

### Head / Tail 哨兵（Sentinel）
约定 `head.next` 是最近使用的、`tail.prev` 是最久未使用的。
两个永不删除的哑节点让**插入和删除都不需要判空、不需要特判首尾** ——
每个操作都是固定的四行指针赋值。这是 LRU 能写得短又不出错的秘诀。

### 最容易漏的一步
淘汰尾部节点时，**只从链表摘掉是不够的，还要 `del map[node.key]`**。
忘了就会内存泄漏，而且后续 `get` 可能拿到一个已经不在链表里的野节点。

> **所以链表节点里必须存 `key`，不能只存 `value`** —— 淘汰时要靠它反查 map。

### 复杂度
`get` / `put` **平均 O(1)**，空间 O(capacity)。
说「平均」是因为链表操作是严格 O(1)，但 Hash Map 最坏是 O(n)。
