# Level 1 · 06 复杂指针与链表数据结构设计

## 核心定义
不是「用链表解题」，而是**用链表做出一个有性能保证的数据结构**。
本章的四道题覆盖了面试里最常考的链表设计场景。

## 决定性观察

### 为什么 LRU 必须用**双向**链表（本章最该理解的一句话）
LRU 需要 O(1) 地把**任意一个**节点挪到最前面。
- Hash Map 给了我们 O(1) 地**拿到那个节点**的能力。
- 但要把它从链表中摘下来，需要它的**前驱**。
- **单向链表拿不到前驱**（只能从头扫，O(n)）。
- **双向链表的节点自己记着 `prev`** ⟹ 摘除就是两行，O(1)。

```python
node.prev.next = node.next
node.next.prev = node.prev
```

### Head / Tail 哨兵（Sentinel）的价值
约定 `head.next` 是最近使用的、`tail.prev` 是最久未使用的。
有了两个永不删除的哑节点，**插入和删除都不需要判空、不需要特判首尾**，
每个操作都是固定的四行。这是 LRU 能写得短又不出错的全部秘诀。

### LRU 最容易漏的一步
淘汰尾部节点时，**只从链表摘掉是不够的，还要 `del map[node.key]`**。
忘了就会内存泄漏，而且后续 `get` 会拿到一个已经不在链表里的野节点。
**所以链表节点里必须存 `key`，不能只存 `value`** —— 淘汰时要靠它反查 map。

### LC-0138 深拷贝：Node Identity vs Node Value
`random` 可能指向链表里**任何**一个节点（包括自己、包括 None）。
深拷贝要求新链表的所有指针都指向**新节点**，一个都不能指回原链表。
- **两趟哈希法**：先建 `原节点 -> 新节点` 的映射，再接 next 和 random。最好讲。
- **一趟 defaultdict 法**（本仓库 `Solution_NC`）：
  `defaultdict(lambda: Node(0))` 让「还没见过的原节点」自动有一个副本占位，
  于是一趟就能把 next 和 random 都接好。
- **交织法（O(1) 额外空间）**：把副本插在每个原节点后面
  （`A -> A' -> B -> B'`），于是 `cur.random.next` 就是副本该指向的节点，
  接完再拆开。思路漂亮，**但不要求同时背两套**。

### LC-0430 多级双向链表
展开顺序就是 **DFS 前序**。用显式栈时，**入栈必须先 `next` 后 `child`**，
这样后进先出才会先处理 child。
双向链表意味着每次接线要写**两条**（`prev.next` 和 `next.prev`），
漏一条的话正向遍历看着没事、反向遍历就崩 —— 这是最隐蔽的坑。
`child` 必须置 None，头节点的 `prev` 必须置 None。

## 复杂度

| 操作 | 复杂度 | 注意 |
|---|---|---|
| LRU get / put | **平均** O(1) | 链表是严格 O(1)，但 Hash Map 最坏 O(n)，所以说「平均/摊还」 |
| LC-0138 两趟哈希 | O(n) / O(n) | 交织法是 O(n) / O(1) |
| LC-0430 栈 | O(n) / O(n) | 原地缝接是 O(n) / O(1) |
| LC-0707 get/addAtIndex | O(index) | 单链表无法做到 O(1) 随机访问 |

## 常见错误
- LRU 淘汰时忘了 `del map[key]`（节点里没存 key 就根本做不到）。
- LRU 用单向链表 ⟹ 摘除节点退化成 O(n)。
- LRU 里 `put` 一个已存在的 key 时把容量也算涨了。
- LC-0138 让新节点的 random 指向了**原节点**。
- LC-0430 入栈顺序写反（先 child 后 next）。
- LC-0430 忘了 `curr.child = None` 或 `dummy.next.prev = None`。

## 面试提示
LRU 用 `OrderedDict` 三行就能写完，但**那基本等于没答** ——
考官要看的就是你能不能手写双向链表。
把 `OrderedDict` 版本当作「工程里我会这么写」的补充说明即可。
