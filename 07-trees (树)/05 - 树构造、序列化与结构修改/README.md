# Level 1 · 05 树构造、序列化与结构修改

## 核心定义
前四章都在**读**树，这一章开始**造树**和**改树**。
三件事：从遍历序列重建、序列化往返、原地重连指针。

## ① 根据遍历序列重建（LC-0105 / LC-0106）

**决定性观察**：
1. **前序的第一个 / 后序的最后一个，就是根。**
2. 在**中序**里找到根的位置，它左边是左子树、右边是右子树 —— 同时得到左右子树的**大小**。
3. 有了大小，就能在前序 / 后序里切出对应的区间，递归。

| | LC-0105（前序 + 中序） | LC-0106（中序 + 后序） |
|---|---|---|
| 根在哪 | 前序的**第一个** | 后序的**最后一个** |
| 递归顺序 | 先左后右 | **先右后左**（因为从后往前消耗后序） |

**为什么必须有中序**：只有前序（或只有后序）无法确定左右子树的分界点。
前序 + 后序**一般情况下不能唯一确定**一棵二叉树（除非是满二叉树）。

**优化**：用 `HashMap: value -> inorder index` 把「找根的位置」从 O(n) 降到 O(1)，
整体 O(n)。**前提是节点值互不相同**（题目保证）。
不用哈希表的话是 O(n²)。

## ② 序列化与反序列化（LC-0297）

**为什么只存节点值不够**：`[1,2]` 既可能是「2 是 1 的左孩子」也可能是右孩子。
**必须保留 null 标记**，结构才能唯一恢复。

两种都可以：
- **前序 + null 标记**：`1,2,#,#,3,#,#`，反序列化时按同样的前序顺序消费。
- **层序 + null 标记**：和 LeetCode 题面的数组表示一致。

反序列化的关键是**用同一个遍历顺序消费 token**，用一个全局游标（或 deque）推进。

## ③ LC-0331 Verify Preorder Serialization —— Slot Counting（槽位计数）

**不要把它当成普通的树递归构造题**，它有一个更漂亮的解法：

把「待填的位置」看成**槽位**：
- 初始有 **1** 个槽位（根的位置）。
- 读到任何一个 token（数字或 `#`），**消耗 1 个槽位**。
- 读到**非空**节点，**产生 2 个新槽位**（它的左右孩子位）。
- 读到 `#`，不产生新槽位。

```python
slots = 1
for tok in preorder.split(','):
    if slots == 0: return False      # 还没读完槽位就空了 → 非法
    slots -= 1
    if tok != '#': slots += 2
return slots == 0                    # 必须恰好用完
```

**为什么中途 slots 不能为 0**：还有 token 没读，说明有节点无处安放。
**为什么结束时必须恰好为 0**：剩余槽位 > 0 表示树没填满（有位置空着没给 `#`）。

## ④ LC-0114 Flatten Binary Tree to Linked List —— 原地重连

目标顺序是**前序**，要求 left 全置 None、只用 right 串起来，且**原地**。

**难点**：`root.right = root.left` 会覆盖掉原来的右子树。两种解法绕开它：

- **反向前序（右 → 左 → 根）** + 一个 `prev`：
  从链表**尾部往前**构建，处理 X 时 X 之后的部分都连好了，改 X 不会丢东西。
  O(n) 时间，O(h) 栈空间。
- **Morris 式穿线**：对每个有左子树的节点，找到**左子树的最右节点**
  （它在前序里正好排在原右子树之前），把原右子树挂上去，再把左子树整体搬到右边。
  O(n) 时间，**O(1) 额外空间** —— 被追问时的加分答案。

## 常见错误
- LC-0105 每层都用 `index()` 在中序里线性找根 ⟹ O(n²)。
- LC-0106 忘了「先递归右子树」（从后往前消耗后序时顺序是反的）。
- LC-0297 省掉 null 标记。
- LC-0114 直接 `root.right = root.left` 而没先保存原右子树。
- LC-0114 忘了把 left 置 None。
