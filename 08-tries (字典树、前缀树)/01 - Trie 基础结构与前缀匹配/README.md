# Level 1 · 01 Trie 基础结构与前缀匹配

## 核心定义
Trie 的全部结构就是 `children: dict[char, TrieNode]` + `is_end: bool`。
本章把这个结构和三个基本操作彻底吃透，后面四章都是它的变体。

## 节点不变量
1. **从根到任意节点的路径 = 一个前缀**；每条边恰好代表一个字符。
2. **`is_end == True`** ⟺ 这条路径构成的字符串是一个**被插入过的完整单词**。
3. **共享前缀 ⟹ 共享节点**：`app` / `apple` / `apply` 的前 3 个字符只占 3 个节点。

## search vs startsWith（最常考的一条）
```python
search("app")      # 必须 walk 成功 AND node.is_end
startsWith("app")  # 只要 walk 成功即可
```
插入了 `"apple"` 之后，`startsWith("app")` 为 True，但 `search("app")` 为 **False**。
**`is_end` 是区分「路径存在」和「单词存在」的唯一标记。**

## 复杂度为什么与单词数量无关
查找 `word` 只沿着它自己的字符走 L 步，每步是一次 dict 查找 O(1)
⟹ **O(L)，与 Trie 里有多少单词无关**。
这就是 Trie 相对「遍历所有单词逐个比较」的根本优势。

空间是 O(Trie 节点数)，上界 O(Σ|w|)，共享前缀越多实际越省。

### LC-0648：为什么「第一个」就是「最短的」
Trie 里从根往下走，路径长度单调递增。
所以沿途遇到的第一个 `is_end`，对应的就是所有匹配词根里**最短**的那个。
`["a","aa","aaa"] + "aaaa"` → `"a"`。

### LC-0720：从「查一个点」到「查一条路径」
条件「w 的每个前缀都在 words 里」翻译成 Trie 语言就是：
**从根到 w 的路径上，每一个节点的 `is_end` 都是 True**。
做法：DFS 时只沿 `child.is_end == True` 的分支往下走。

字典序最小：按 `sorted(children)` 遍历，且**只在严格更长时更新答案** ——
这样同长度时先到达的（字典序小的）会被保留。

它也有一个漂亮的非 Trie 解法：排序后用 set 增量构建
（`if len(w)==1 or w[:-1] in seen`）—— 排序同时保证了「短的先处理」和「同长按字典序」。

## 重复插入
同一个单词插两次是幂等的（路径已存在，只是再置一次 `is_end`）。
**但如果节点上挂了计数（见 Level 1 `03` 的 LC-2416），重复插入必须照常累加。**

## 常见错误
- `search` 忘了检查 `is_end`。
- `startsWith` 多检查了 `is_end`。
- 用 `node.children[c] = TrieNode()` 直接覆盖（会丢掉已有子树）——
  要用 `setdefault` 或先判断存在。
- LC-0648 找到匹配后继续往下走（应该立刻停，否则得到的不是最短）。
- LC-0720 用 `>=` 更新答案 ⟹ 同长度时会被字典序大的覆盖。
