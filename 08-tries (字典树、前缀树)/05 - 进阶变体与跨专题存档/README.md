## 01 - Bitwise Trie 与最大 XOR（LC-0421）

**核心转换：把整数看成固定长度的 0/1 字符串，Trie 的边从 26 个字母变成 2 个 bit。**

先明确 XOR：**两位不同才得 1**。所以要让 XOR 大，就要让**高位尽量不同**。

### 三个关键点
1. **必须从最高位开始**。因为 `2^k > 2^(k-1) + ... + 2^0` ——
   高位的 1 比后面所有位加起来都值钱，所以贪心地优先让高位取 1 **永远不亏**。
   这是本题贪心成立的全部理由。
2. **查询时优先走与当前位相反的分支**（相反 ⟹ 这一位 XOR 出 1）；
   那条分支不存在才退而走相同的。
3. **TrieNode 只有两个 children**（`0` 和 `1`），比字符 Trie 简单得多。

### 复杂度
**O(n × B)**，B 是位宽（31 或 32），即 O(31n) ≈ O(n)。
对比暴力两两异或 O(n²) —— n = 2×10⁵ 时暴力 4×10¹⁰ 必然超时。

### 还有一个不用 Trie 的解法
从高位往低位逐位确定答案：每一位先假设能填 1，
用 `a ^ b = target ⟺ a ^ target = b` 在 Hash Set 里验证。同样 O(31n)，代码更短。
两种都值得会。

**为什么只标 P2**：它属于 Bit Manipulation + Trie 的组合，
不是 FAANG 准备的核心必背模板。但「Trie 的边不一定是字母」这个认知很有价值。

## 02 - Common Prefix 的非 Trie 主流解法

### LC-0014 Longest Common Prefix（P2）
**Trie 不是必需的，而且通常不划算。** 主流解法：
- **纵向扫描**：逐列比较所有字符串的第 i 个字符，一不同就停。O(Σ|s|)。
- **排序后比首尾**：排序后只需比较第一个和最后一个字符串的公共前缀。O(n log n · L)。
- 分治 / 二分长度也都可以。

建 Trie 要 O(Σ|s|) 的额外空间，而这题只查询一次 —— **开销不划算**。
它本质是**基础字符串题**，放在本专题只是因为概念相关。

**跨专题合并（2026-11-11）**：`99-advanced (进阶专题)/divide-and-conquer (分治)/` 下原本
另有一份实体目录（代码是纵向扫描，与本目录的 Trie 解法不同）。已合并到这里，原目录移入废纸篓
⟹ 全仓库 LC-0014 只剩这一份。合并后 `solution.py` 里有**六种解法**：

| | 解法 | 时间 | 空间 |
|---|---|---|---|
| `Solution` | Trie 的「不分叉链」（原有代码） | O(S) 建树 + O(m) 查询 | O(S) |
| `Solution_2` | 横向扫描 | O(S) | O(1) |
| `Solution_3` ⭐️ | 纵向扫描（从 99-advanced 原样搬入） | O(S) | O(1) |
| `Solution_4` | 分治（这才是真的分治） | O(S) | O(m·log n) |
| `Solution_5` | 二分答案 | O(S·log m) | O(1) |
| `Solution_6` | 排序后比首尾 | O(n·L·log n) | O(n·L) |

六种解法 + 定义真值做了 20000 组随机对拍，全部一致。

### LC-3043 Find the Length of the Longest Common Prefix（P2）
求两个**整数数组**之间最长的公共**数字**前缀。

**必须区分 String Trie 和 Digit Trie**：
这里的「字符」是十进制数位（0–9），不是字母。

最简单的解法是 **Hash Set**：把 arr1 里每个数的所有前缀（`x`, `x//10`, `x//100`, ...）
塞进 set，再对 arr2 的每个数的每个前缀去查，取最长命中。
O(Σ 位数)，比建 Trie 更直接。

Trie 也可行（每个节点 10 个 children），但收益有限。

## 03 - 字符串区间标注（LC-0616 Add Bold Tag in String）

**它不是典型的 Trie 题**，核心是**区间合并**：
1. 对每个 word，找出它在 s 中的所有出现位置 ⟹ 得到一堆区间 `[i, i+len(word))`。
2. **把重叠或相邻的区间合并**（这一步是本题的真正难点，属于区间问题）。
3. 按合并后的区间插入 `<b>` / `</b>`。

找出现位置可以用 Trie 加速（从每个位置 i 出发沿 Trie 走），
也可以直接用 `s.find` / KMP。**合并区间的逻辑和用什么匹配方式无关。**

更合适的归属其实是 [14-intervals (区间)](<../../14-intervals (区间)/>)，
本目录保留原有资料并在此说明。

## 本章小结：什么时候**不该**用 Trie

| 情况 | 更好的做法 |
|---|---|
| 只查询一次 | 直接扫描 / 排序（LC-0014） |
| 字符集是数字且前缀少 | Hash Set（LC-3043） |
| 真正的难点在区间合并 | 先解决区间问题（LC-0616） |
| 父子路径判断 | 排序 + 前缀检查（LC-1233，见 Level 1 `03`） |

**Trie 的优势是「多次前缀查询」和「共享前缀的批量匹配」。**
不满足这两条时，Trie 往往是过度设计。
