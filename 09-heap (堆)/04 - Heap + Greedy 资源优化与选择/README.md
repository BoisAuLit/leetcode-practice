# Level 1 · 04 Heap + Greedy 资源优化与选择

## 核心定义
贪心决定**选什么**，堆负责**快速找到该选的那个**。
本章的每道题都要回答两件事：**贪心策略是什么？为什么它正确？**

> **堆只是加速器。** 如果贪心策略错了，用再快的堆也没用。
> 所以每道题的 solution.py 里都写了交换论证或等价说明。

## 01 - Optimal Merge Pattern（LC-1167）

**策略**：每次合并**当前最短的两根**棍子。

**为什么正确**：合并代价 = 两根长度之和，而合并产生的新棍子**还要参与后续合并**。
所以一根棍子被计入总代价的次数 = 它在合并树中的**深度**。
要让总代价最小，就要让长的棍子深度浅 ⟹ 这正是 **Huffman 编码**的构造。
每次取两个最小的，就是 Huffman 的贪心步骤。

O(n log n)，空间 O(n)。

## 02 - 有限资源的最优分配（LC-1642）

**策略**：先无脑用**梯子**，当梯子用完时，把**到目前为止用梯子的那些跳跃里最小的那个**
改成用砖块。

**为什么正确（反悔贪心 / Regret Greedy）**：
梯子应该留给最大的跳跃。但我们是顺序遍历的，不知道后面会不会有更大的跳跃。
于是先假设都用梯子，**一旦发现梯子不够，就从已用的里面"反悔"掉最小的那个**，
改用砖块。这样梯子始终分配给「已见过的最大的 L 个跳跃」。

实现：一个**最小堆**装「当前用梯子的跳跃高度」，超过 L 个就弹出最小的去花砖块。

**这个「先占坑、不够了再反悔最差的」套路**在很多题里出现，值得单独记住。

O(n log L)，空间 O(L)。

## 03 - 频率重排与边际收益

### LC-0767 Reorganize String
**策略**：每次取**当前剩余次数最多**的字符，但**不能和上一个相同**。

实现：最大堆按剩余次数排。每次弹出堆顶，如果它和上一个字符相同，
就弹第二个用，再把第一个放回去。或者更简洁：
**取出堆顶后先不放回，等下一轮放回**（这样它必然隔了一个位置）。

**无解判定**：若某个字符出现次数 > `(n + 1) // 2`，无论怎么排都会相邻 ⟹ 返回 `""`。
这个判定要在最前面做。

### LC-1792 Maximum Average Pass Ratio
**策略**：每次把一个名额给「**边际收益最大**」的班级。

边际收益 = `(pass+1)/(total+1) − pass/total`。

**为什么能贪心**：这个边际收益对同一个班级是**递减**的
（给得越多，再给一个的提升越小）。所以「每次选当前边际最大的」不会后悔 ——
这是经典的**凸性 / 递减收益**条件下贪心成立的理由。
堆里按边际收益排（取负做最大堆）。

**注意**：堆里存的是浮点数，比较时要小心精度；按边际收益排序而不是按比率排序。

O(k log n)。

## 04 - 排序与 Heap 的组合选择（本章最该掌握的套路）

> **遇到两个相互牵制的维度：排序固定一个，堆优化另一个。**

| | LC-0502 IPO | LC-2542 Maximum Subsequence Score |
|---|---|---|
| 排序哪个维度 | `capital` **升序** | `nums2` **降序** |
| 排序用来干嘛 | **解锁**（资本够了才能做） | **枚举最小值**（降序遍历时当前元素就是候选池最小值） |
| 堆里放什么 | `profit`，**最大堆** | `nums1`，**最小堆** |
| 堆用来干嘛 | 从可选集合里**挑最好的** | 维护 **Top-K 和**，踢掉最差的 |
| 复杂度 | O(n log n + k log n) | O(n log n + n log k) |

### LC-0502 的贪心正确性（交换论证）
设最优解某轮没选当前可做的最大利润项目 P，而选了 Q（profit(Q) < profit(P)）。
换成 P：资本变得**不小于**原来 ⟹ 后续能做的项目只多不少 ⟹ 总利润不减。
重复替换即可把最优解变成贪心解。∎
（前提：**利润非负**，做项目只会让资本变大。）

### LC-2542 为什么降序排
降序保证「遍历到 i 时，前面所有 nums2 都 >= nums2[i]」
⟹ **如果最小值取 nums2[i]，候选池恰好是前 i+1 个** ⟹ 可以增量维护。
升序排的话候选池随遍历缩小，没法「加入 + 弹最小」。

## 常见错误
- LC-0767 忘了先判 `max_count > (n+1)//2` 无解。
- LC-0767 把堆顶立刻放回去 ⟹ 相邻重复。
- LC-1642 用最大堆（应该用最小堆来「反悔掉最小的」）。
- LC-1792 按比率而不是**边际收益**排序。
- LC-0502 / LC-2542 的复杂度只说堆那部分，**漏掉排序的 O(n log n)**。
- LC-2542 把 nums2 升序排。

## 复习时的 Pattern Recognition
> 「最小化合并代价」 → Huffman，取两个最小。
> 「有限的特权资源（梯子/免费次数）」 → 反悔贪心，最小堆存已用的。
> 「两个维度相互牵制」 → **排序一个 + 堆优化另一个**。
> 写之前先问：**我的贪心为什么对？** 能不能给一个交换论证。
