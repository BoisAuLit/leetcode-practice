# Level 1 · 05 Heap + Scheduling 任务调度

## 核心定义
**事件驱动模拟**：维护一个「当前时间」，用堆维护「现在可以做的事」，
按时间推进，每一步从堆里挑最该做的那个。

## 通用骨架
```python
tasks.sort(key=按到达时间)            # 用指针顺序「释放」已到达的任务
heap, now, i = [], 0, 0
while 还有未完成的任务:
    while i < n and tasks[i].arrive <= now:
        heapq.heappush(heap, (优先级, ...)); i += 1
    if not heap:
        now = tasks[i].arrive          # ★ 时间跳跃，绝不逐秒推进
        continue
    取堆顶执行; now += 耗时
```

**「时间跳跃」是本章最关键的工程细节**：时间范围常达 10⁹，
逐秒循环必然 TLE。用 `now = max(now, 下一个任务的到达时间)`。

## 01 - Frequency Scheduling 与 Cooldown（LC-0621 Task Scheduler）

**两种解法，都要会**：

**① 堆模拟**：最大堆按剩余次数排。每一轮（长度 n+1 的周期）尽量取出 n+1 个不同任务，
执行完把剩余次数 > 0 的放回去。直观但代码长。

**② 数学公式（更优）**：
```
maxf  = 出现次数最多的任务的次数
cnt   = 有多少个任务达到了 maxf
answer = max(len(tasks), (maxf - 1) * (n + 1) + cnt)
```
**为什么**：把出现最多的任务排成骨架，中间插 n 个空位，
得到 `(maxf-1)` 个完整周期 + 最后一批 `cnt` 个。
如果任务种类足够多，空位全被填满，答案就退化成 `len(tasks)` ——
所以要取 max。O(n) 时间、O(1) 空间（26 个字母）。

## 02 - 动态任务与事件优先级

### LC-1834 Single-Threaded CPU
和 LC-0502 IPO **同一个骨架**（排序解锁 + 堆选最优），只是：
- 解锁条件是「到达时间 <= now」而不是「资本够」
- 堆里取 **processingTime 最小**（而不是 profit 最大），平局按**原始下标**

两个细节：
- 排序前必须 `enumerate` 保留**原始下标**（输出要下标，平局也按下标）。
- 堆的键直接写成 `(processingTime, index)`，平局规则就自动满足了。

### LC-1353 Maximum Events（Earliest Deadline First）
**策略**：每天参加「所有当前可参加的会议里，**结束最早**的那个」。

**为什么**：结束早的会议机会窗口最窄，再不参加就过期；结束晚的以后还有机会。

**最容易混的一点**：这**不是**区间调度（LC-0435 那种按 end 排序贪心）。
区间调度要求「占满整个区间」，而本题**每个会议只占一天** ——
所以同一个会议可以等到它区间里的任意一天再参加，
必须用堆**动态维护当前可选集合**，每天做一次选择。

实现：按 start 排序入堆（堆里存 **end**），每天先清理 `end < day` 的过期会议，再弹一个。

### LC-2402 Meeting Rooms III（**两个堆**）
- `free`：空闲房间，按**房间编号**的最小堆 ⟹ 满足「优先用编号最小的」
- `busy`：占用中，按**结束时间**的最小堆，元素是 `(end, room)`

每个会议前，先把 `busy` 里所有 `end <= start` 的房间**搬回** `free`。
然后：有空房就用编号最小的；没空房就等最早结束的那个。

**最容易写错的一行**：等待时新的结束时间是 `e + (end - start)`，
**不是 `end`** —— 会议**时长不变**，只是整体后移。

和 **LC-0253 Meeting Rooms II** 的区别：
253 只问「最少几个房间」，一个堆存 end 就够，不关心房间编号；
2402 房间数固定、要**具体分配**、还要**排队等待** ⟹ 必须两个堆。
LC-0253 实体目录在 [14-intervals](<../../14-intervals (区间)/>)。

## 复杂度
全部 **O(n log n)**（排序主导 + 每个任务常数次堆操作）。
LC-0621 的公式解法是 O(n) / O(1)。

## 常见错误
- 逐秒推进时间（TLE）。
- LC-1834 排序后丢了原始下标。
- LC-1353 套用区间调度（按 end 排序后贪心取不重叠）。
- LC-1353 忘了清理过期会议。
- LC-2402 等待时把结束时间写成 `end` 而不是 `e + (end - start)`。
- LC-2402 平局时没取编号最小的房间。

## 复习时的 Pattern Recognition
> 「任务陆续到达，空闲时挑一个做」 → 排序解锁 + 堆选最优 + 时间跳跃。
> 「每个时间点只能选一个，每个候选有截止期」 → Earliest Deadline First。
> 「固定数量的资源 + 排队等待」 → 两个堆（空闲 / 占用）。
