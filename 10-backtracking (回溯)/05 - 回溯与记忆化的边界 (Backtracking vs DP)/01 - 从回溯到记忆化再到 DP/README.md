## 为什么这道题值得在回溯专题留一个位置

本专题前四章的题（子集、排列、分割、N 皇后）都**必须**列出每一个方案，
所以回溯是唯一选择 —— 答案规模本身就是指数级的。

**LC-0494 是那条分界线**：它只要「方案**数**」，不要方案本身。
一旦只要数量，不同的搜索分支就可能汇合到同一个状态，于是可以合并、可以 DP。

## 判据（一句话）

> **要列出所有方案 ⟹ 只能回溯**（答案规模就是指数级，没有更快的可能）。
> **只要数量 / 最优值 / 能否达成 ⟹ 先找「状态」，能合并分支就上记忆化或 DP。**

**为什么能合并**：如果两条不同的搜索路径走到了**同一个状态**，
而且后续结果只取决于这个状态（和走法无关），那它们的子问题就是同一个 ——
算一次就够。回溯慢，就是因为它把同一个子问题反复算了很多遍。

## LC-0494 的三级演进（细节在那份 solution.py 里）

```
① 朴素回溯 O(2^n)
       ↓   发现「走到第 i 个数时，前面怎么选无所谓，只有累计和 cur 影响后续」
② 记忆化 O(n · S)，状态 = (i, cur)
       ↓   发现 P + N = sum、P − N = target ⟹ P = (sum+target)/2
③ 子集和 01 背包 O(n · sum)
```

**找到「状态」是唯一的思考步骤**，剩下都是机械变换。

两个无解判定（必须先做）：`(sum + target)` 为奇数、或 `abs(target) > sum`。
经典边界：`[0,0,0,0,0,0,0,0,1]`, target=1 → **512**（8 个 0 各有 ±两种选法）。

## 面试里怎么答
先说朴素回溯 + 复杂度，再指出状态可合并 ⟹ 记忆化，最后给背包版本。
**这个「从暴力推进到最优」的过程本身就是加分项**，比直接甩出背包代码更能说明理解。
