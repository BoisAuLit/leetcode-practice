## 开头:先分清"结果"和"过程"

一个 MST 算法有两样东西可以复用:

- **结果**:算法跑完得到的那棵树(总价最小、把所有点连通、恰好 n − 1 条边)。
- **过程**:算法是怎么一步步得到这棵树的。Kruskal 的过程是"把边按价格从低到高排队,逐条接上,用并查集记录谁和谁已经连通,两头已连通的边拒绝";Prim 的过程是"从一个点出发,每次买圈子边界上最便宜的一根线,圈子一圈圈长大"。

第一层用的是结果;第二、三层用的是 Kruskal 的过程;第四层用的是 Prim 的过程;第五层是现实应用。

## 第一层:伪装成别的故事的 MST(建模题)

**什么叫建模**:题目讲了一个故事(城市、水井、坐标点),你要把故事翻译成"点是什么、线是什么、线的价格是什么",翻译完发现它就是"把所有点连通、总价最小",那就是 MST。常见的三种伪装:

- **每个点可以"自建"**(自己打井、自己建电站):加一个虚拟点,"自建"翻译成"和虚拟点之间拉一根线,价格就是自建费用"。
- **要最大而不是最小**:把所有价格取负,或者排序时从大到小,算法一字不改,得到最大生成树。
- **图可能不连通**:Kruskal 跑完 `used < n − 1` 就说明连不起来;Prim 堆版 `count < n`、数组版遇到 `inf` 同理。

题目:

- **LC 1584 Min Cost to Connect All Points**
  题目在问:平面上 n 个点,任意两点可以拉线,费用是曼哈顿距离 |x₁−x₂| + |y₁−y₂|,把所有点连通最少花多少。
  怎么套:点就是点,任意两点之间都有线,是完全图。完全图边数 ≈ n²/2,用 Prim 数组版 O(n²) 最合适,不用把边造出来。

- **LC 1135 Connecting Cities With Minimum Cost**
  题目在问:n 座城市编号 1..n,给一张可修道路的清单 [城市 a, 城市 b, 费用],把所有城市连通最少花多少;连不起来返回 −1。
  怎么套:裸 MST,但图是稀疏的(边数和点数同量级)且可能不连通。用 Kruskal 或 Prim 堆版,记得编号从 1 开始要多开一格。

- **LC 1168 Optimize Water Distribution in a Village**
  题目在问:n 户人家,每家要么自己打井(第 i 家打井花 wells[i]),要么用水管接到已经有水的邻居(修某段水管花 cost)。每家都要有水,总费用最少是多少。
  怎么套:加一个 0 号虚拟点代表"水源"。第 i 家打井 = 在 0 和 i 之间拉一根价格 wells[i] 的线;水管就是普通的线。在 n + 1 个点上跑 MST。
  为什么对:每家"有水"等价于"能通过线走到 0 号点"——走到 0 号的那最后一根线就是某家的井,路上的其他线就是水管。所以"每家都有水、总费用最少"就是"n + 1 个点全连通、总价最少",正是 MST。

## 第二层:追问 MST 的结构(只有 Kruskal 做得到)

**先讲清两个术语。** 当多条边价格相同时,最小生成树可能不止一棵——总价一样,选的边不一样。于是每条边有三种身份:

- **关键边 (critical edge)**:每一棵 MST 都必须含它。把它从图里删掉,要么总价变大,要么图直接连不起来。
- **伪关键边 (pseudo-critical edge)**:至少有一棵 MST 含它,但不是每棵都含。意思是"用它也能凑出最小总价,不用它也行"。
- **无关边**:任何 MST 都不含它。

小例子:三角形 1–2 价格 1、2–3 价格 2、1–3 价格 3。唯一的 MST 是 {1–2, 2–3},总价 3。1–2 和 2–3 是关键边,1–3 是无关边。换成三条边价格全是 1:任选两条都是 MST,总价 2,三条边都是伪关键边。

**怎么用 Kruskal 检验一条边 e 的身份——跑三种 Kruskal:**

1. **正常跑**,得到最小总价 base。
2. **排除 e 再跑**:循环里遇到 e 直接跳过,当它不存在。得到的总价如果比 base 大、或者连不起来(凑不够 n − 1 条),说明没有 e 就达不到最小,e 是关键边。
3. **强制先买 e 再跑**:在排序循环开始之前,先手动把 e 的两头 `union`、把 e 的价格加进 total、`used` 记 1,然后再正常跑剩下的边。这样 e 百分之百在最后的树里。得到的总价如果等于 base,说明存在一棵含 e 的 MST;如果 e 又没通过第 2 步的关键边检验,那它就是伪关键边。
   为什么第 3 步成立:先买 e 再跑 Kruskal,得到的是"所有含 e 的生成树里最便宜的那棵"。它的价格等于 base,就证明含 e 也能达到最小。

```python
def findCriticalAndPseudoCriticalEdges(n, edges):
    order = sorted(range(len(edges)), key=lambda i: edges[i][2])   # 按价格排好的边编号

    def mst_cost(skip=-1, force=-1):
        uf = UnionFind(n); total = used = 0
        if force != -1:                            # 强制先买:循环开始前就把这条边买下
            u, v, w = edges[force]
            uf.union(u, v); total += w; used += 1
        for i in order:
            if i == skip:                          # 排除:这条边当作不存在
                continue
            u, v, w = edges[i]
            if uf.union(u, v):
                total += w; used += 1
        return total if used == n - 1 else inf     # 连不起来 = 无穷大

    base = mst_cost()
    critical, pseudo = [], []
    for i in range(len(edges)):
        if mst_cost(skip=i) > base:
            critical.append(i)
        elif mst_cost(force=i) == base:
            pseudo.append(i)
    return [critical, pseudo]
```

Prim 做不了这件事,因为 Prim 是"圈子长大"的过程,没有"逐条审批边"的环节,没法说"跳过这条边"或"先买这条边"。

- **LC 1489 Find Critical and Pseudo-Critical Edges in Minimum Spanning Tree**
  题目在问:给 n 个点和边列表 [u, v, 价格],返回两个列表:关键边的下标、伪关键边的下标。
  怎么做:就是上面的代码。边数 ≤ 100,对每条边跑两次 Kruskal 完全来得及。

- **LC 1579 Remove Max Number of Edges to Keep Graph Fully Traversable**
  题目在问:n 个点,边分三种:类型 1 只有 Alice 能走,类型 2 只有 Bob 能走,类型 3 两人都能走。最多删掉多少条边,仍然保证 Alice 和 Bob 各自都能走遍所有点;做不到返回 −1。
  怎么做:给 Alice 和 Bob 各一个并查集。**先处理类型 3**:在两个并查集里都 union,如果两边都返回 False(两人都已经连通这两点),这条边多余,可删。再处理类型 1(只进 Alice 的并查集)和类型 2(只进 Bob 的),union 失败的可删。最后检查两个并查集是否都只剩一派,否则 −1。
  为什么先处理类型 3:一条类型 3 的边一个人干两个人的活,价值更高。Kruskal 按价格排序是"便宜的先审";这里按"价值高的先审",同一个思想。本质就是 Kruskal 的"拒绝成圈边"数了两遍。

- **LC 684 Redundant Connection**
  题目在问:一棵 n 个点的树,多加了一条边(所以有 n 条边),找出那条多余的边;有多个答案时返回输入里最后出现的那条。
  怎么做:按输入顺序逐条 union,第一条 union 返回 False 的边就是答案。
  为什么对:n 个点 n 条边恰好有一个环,这条边是环上最后被加入的边,而且题目要求返回最后出现的那条,正好就是它。这是 Kruskal 的拒绝那一步,不需要排序、不需要价格。

- **LC 1319 Number of Operations to Make Network Connected**
  题目在问:n 台电脑和一堆网线,一次操作可以拔下一根网线插到别的两台之间,最少几次操作让所有电脑连通;做不到返回 −1。
  怎么做:先看网线总数够不够 n − 1,不够直接 −1(网线少于 n − 1 根不可能连通)。够的话,用并查集数现在有几派 k,答案是 k − 1。
  为什么对:k 派要连成一派至少需要 k − 1 根线;union 失败的那些网线就是多余的,可以拔下来用,而网线总数 ≥ n − 1 保证多余的够用。

## 第三层:瓶颈路径与阈值连通(用 Kruskal 的过程,不要那棵树)

**先讲清"瓶颈"。** 一条路径上最贵(最高、最难)的那一段叫这条路径的瓶颈 (bottleneck)。"最小瓶颈路径"(minimax path)是指:在所有从 u 到 v 的路径里,选瓶颈最小的那条。它和最短路不一样:最短路比的是**总和**,瓶颈路径比的是**最大值**。比如从家到公司有两条路:一条总长 10 公里但有一段 5 公里的烂路,另一条总长 14 公里但最烂的一段只有 2 公里。最短路选第一条,最小瓶颈路径选第二条。"路径上最小值最大"(maximin)是镜像问题,比如运货卡车找一条路,路上限高最低的那座桥要尽量高。

**阈值连通的想法。** 换个角度看瓶颈:设一个门槛 x,规定"只允许走价格 ≤ x 的边",问 u 和 v 通不通。x 很小时肯定不通,x 很大时肯定通,中间有一个临界值——**让 u、v 第一次连通的那个 x,就是 u 到 v 的最小瓶颈值**。因为 x 刚好够大时,存在一条全部边都 ≤ x 的路,它的瓶颈 ≤ x;而 x 再小一点就不存在这样的路,所以瓶颈不可能更小。

**Kruskal 的过程正好就是"让 x 从小到大涨"。** 它按价格从低到高接边,接到价格为 x 的边时,所有 ≤ x 的边都已经接上了——这时并查集里"谁和谁一派"就等于"门槛为 x 时谁和谁连通"。所以之前那句抽象的"排序 → 按阈值逐个加入 → 并查集合并 → 在某个时刻读答案",具体写出来是四步:

1. **排序**:把边按价格从小到大排好(格子题则把格子按高度排好)。
2. **逐个加入**:按顺序一条条取出来,取到的这条边的价格就是当前门槛 x。
3. **合并**:`uf.union(u, v)`,把这条边两头记成一派。这一步**不需要**判断成不成环,因为我们不是在建树,只是在记录连通性,union 返回什么无所谓。
4. **读答案**:每合并一次就检查一下你关心的那两个点是否 `find` 相同;第一次相同的那一刻,当前门槛 x 就是答案。

**多组查询 → 离线处理 (offline)。** 如果有很多组 (u, v, limit) 要问"只用 < limit 的边 u、v 通不通",一组一组分别跑太慢。办法是:先把所有查询读进来,按 limit 从小到大排序,再按这个顺序回答——门槛只会越涨越高,边只会越加越多,从不需要拆边,所以用一个指针 k 记录"边加到哪了",每个查询先把所有 < limit 的边补加进去,再问并查集。最后把答案按查询的原顺序放回去。"离线"就是指"允许先看完所有问题再决定回答顺序"。

```python
def distanceLimitedPathsExist(n, edgeList, queries):                  # LC 1697
    edgeList.sort(key=lambda e: e[2])                                 # ① 边按长度排队
    order = sorted(range(len(queries)), key=lambda i: queries[i][2])  #   查询按 limit 排队
    uf = UnionFind(n)
    ans = [False] * len(queries)
    k = 0                                                             # 边加到哪了
    for qi in order:
        p, q, limit = queries[qi]
        while k < len(edgeList) and edgeList[k][2] < limit:           # ② 把所有 < limit 的边
            uf.union(edgeList[k][0], edgeList[k][1])                  # ③ 接上
            k += 1
        ans[qi] = uf.find(p) == uf.find(q)                            # ④ 此刻通不通就是答案
    return ans
```

**格子图怎么变成图。** 每个格子是一个点,上下左右相邻的格子之间有边。如果题目的"难度"写在格子上(高度),就把格子按高度排序逐个"开放",开放一个格子时和已开放的邻居 union;如果难度写在相邻关系上(高度差),就把相邻对按高度差排序当作边。

**时间倒放。** 如果题目是"随着时间推移东西被删掉,问最后能撑到什么时候",并查集只会合并不会拆分,正着做不了;但把时间倒过来,"删掉"就变成"加回来",又成了逐个加入的过程。

  题目在问:n × n 网格,每格有个高度,水位在 t 时刻涨到 t,只能在高度 ≤ t 的格子之间游动。最早什么时候能从左上角游到右下角。

## 第四层:从一个起点出发的瓶颈路径(Prim / Dijkstra 的骨架改 relax)

第三层是多点、多查询的工具;如果只问"从一个固定起点到某个终点",用 Prim 堆版的骨架更短。先看三个算法共用的骨架:

1. 堆里放 (标签, 点),起点标签为 0(或起点自己的值)。
2. 每次弹出标签最小的点;已经确定过的点是作废票,跳过。
3. 确定这个点,然后对它的每个邻居算一个新标签,比旧标签小就压进堆(这一步叫 **relax**,松弛)。

三个算法**只有 relax 这一行不一样**,因为"标签"的含义不一样:

| 算法 | 标签的含义 | 从 u 到邻居 v 的新标签 |
|---|---|---|
| Prim | 把 v 拉进圈最便宜的一根线 | `w` |
| Dijkstra | 从起点到 v 的最短总路程 | `d + w` |
| 最小瓶颈(minimax) | 从起点到 v 的路径上最大边最小是多少 | `max(d, w)` |
| 最大最小(maximin) | 从起点到 v 的路径上最小边最大是多少 | `min(d, w)`,配大根堆(标签取负) |

为什么 `max(d, w)` 是对的:到 u 为止路径的瓶颈是 d,再走一条价格 w 的边,新路径的瓶颈就是两者的较大者。堆每次弹最小标签,等于每次确定"目前瓶颈最小的那个点",和 Dijkstra 每次确定"目前最近的点"是同一个道理。

```python
def swimInWater(grid):                                         # LC 778,Dijkstra 骨架
    n = len(grid)
    best = [[inf] * n for _ in range(n)]
    best[0][0] = grid[0][0]
    heap = [(grid[0][0], 0, 0)]                                # (到这格为止路径上的最高点, r, c)
    while heap:
        d, r, c = heappop(heap)
        if (r, c) == (n - 1, n - 1):
            return d
        if d > best[r][c]:                                     # 作废票
            continue
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < n and 0 <= nc < n:
                nd = max(d, grid[nr][nc])                      # relax 写 max,不是 d + w
                if nd < best[nr][nc]:
                    best[nr][nc] = nd
                    heappush(heap, (nd, nr, nc))
```

题目:778、1631、1102 这三题都可以用这个骨架解,和第三层是同一批题的另一种解法。选法:**单起点单终点,用本层(代码最短);多组查询、要离线、或者要反着时间走,用第三层**。这三题其实还有第三种解法——二分答案 + BFS 检查通不通——面试时能说出三种并解释取舍是加分项。

## 第五层:LeetCode 之外的真实用途

- **聚类(single-linkage 层次聚类)**:把数据点之间的距离当边,跑 Kruskal,但在**剩 k 派时停下**,这 k 派就是 k 个簇。等价于建完 MST 后砍掉最贵的 k − 1 条边。它保证的是"不同簇之间的最小距离尽量大"——因为砍掉的恰好是最长的那些连接。做 embedding 去重、文档聚类时是基础方法之一。
- **旅行商问题 (TSP) 的 2 倍近似**:TSP 要求最短的、经过所有点一次的回路,没有快速精确解。但 MST 的总价一定 ≤ 最优回路(回路去掉一条边就是一棵生成树,而 MST 是最便宜的生成树);沿 MST 做一遍先序遍历、每条边走两次,总长 ≤ 2 × MST ≤ 2 × 最优;再把重复经过的点跳过(距离满足三角不等式时跳过不会更长),得到一条不超过最优 2 倍的回路。
- **图像分割**:像素是点,相邻像素颜色差是边权,按边权从小到大合并,合并时加一个"差异是否够小"的判断,就把图像分成颜色相近的区域(Felzenszwalb 算法)。
- **随机迷宫**:给网格的每条边一个随机权重跑 Kruskal 或 Prim,得到的树没有环、处处可达,就是一张迷宫。
- **网络设计**:布电缆、铺管道、电路板走线,就是 MST 的原产地。

---

## 它们做不了的事(同样要记)

- **有向图**:有向图上"从根出发能到所有点、总价最小"的树叫最小树形图,Prim 和 Kruskal 都不适用,要用朱–刘/Edmonds 算法。
- **MST 上的路不是最短路**:三角形 A–B 1、B–C 1、A–C 1.5,MST 是 {A–B, B–C},树上 A 到 C 要走 2,但直接走 A–C 只要 1.5。想要距离最短用 Dijkstra;MST 上的路径保证的是瓶颈最小,不是总和最小。
- **限制度数的生成树、Steiner tree**(只需连通指定的几个点,可以借用其他点):都是 NP-hard,MST 只能给近似解。

## 复习速查表

| 题目的问法 | 用什么 |
|---|---|
| 把所有点连通、总代价最小(可能换了故事) | MST 本身,先建模(虚拟源点 / 取负 / 判不连通) |
| 哪些边必须要、哪些可有可无、最多删几条 | Kruskal,排除 / 强制先买 / 数拒绝次数 |
| 路径上最大值最小、最小值最大 | 最小瓶颈路径:Kruskal 过程看何时连通,或 Dijkstra 改 relax 为 max/min |
| 很多组"只用 ≤ x 的边通不通" | 离线:查询按 x 排序 + Kruskal 过程 |
| 东西随时间被删,问最后能撑到何时 | 时间倒放,变成逐个加入 |
| 按点的值从小到大的统计 | 同一个过程,门槛换成点的值 |
