# Level 1 · 05 字符串分割与双序列 DP

两类问题：
- **单字符串分割**（01）：`dp[i]` = 前 i 个字符的答案，枚举「最后一段从哪开始」。
- **双序列**（02–04）：`dp[i][j]` = s 的前 i 个和 t 的前 j 个的答案。

## 01 - 单字符串分割与解码

```python
dp[0] = 初始值
for i in range(1, n + 1):
    for j in range(i):                  # 枚举最后一段 s[j:i]
        if 合法(s[j:i]):
            dp[i] = 合并(dp[i], dp[j])
```

| 题 | `dp[i]` 的含义 | 「合法」是什么 |
|---|---|---|
| **LC-0091** Decode Ways | 前 i 个字符的解码方案数 | 一位（非 `'0'`）或两位（`10`–`26`） |
| **LC-0139** Word Break | 前 i 个字符能否拆分 | `s[j:i] in wordDict` |
| **LC-3291** Min Valid Strings | 前 i 个字符最少几段 | 是 words 中某个单词的**非空前缀**（用 Trie 加速） |

**LC-0091 的三个坑**（这题的全部难度在边界）：
1. `'0'` **不能**单独解码 ⟹ `s[i-1] != '0'` 才能取一位。
2. 两位必须在 `10`–`26` 之间 ⟹ `'06'` 不合法（前导零）。
3. `dp[0] = 1`（空串算一种解法），`s[0] == '0'` 时直接返回 0。

**LC-0139 vs LC-0140**：前者只要 bool ⟹ 纯 DP；
后者要**所有拆分方案** ⟹ 必须回溯（见 [10-backtracking](<../../10-backtracking (回溯)/README.md>)）。

## 02–04 - 双序列 DP 的统一骨架

```python
dp = [[init] * (n + 1) for _ in range(m + 1)]
# 边界：dp[i][0] 和 dp[0][j]
for i in range(1, m + 1):
    for j in range(1, n + 1):
        if s[i-1] == t[j-1]:
            dp[i][j] = dp[i-1][j-1] (+1)              # 字符匹配：取对角线
        else:
            dp[i][j] = min/max(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) (+1)
```

**三个方向的含义**（编辑距离里最清楚）：
| 方向 | 操作 |
|---|---|
| `dp[i-1][j-1]` | **替换**（或字符相同时「什么都不做」） |
| `dp[i-1][j]` | **删除** s 的第 i 个字符 |
| `dp[i][j-1]` | **插入**一个字符（= 删除 t 的第 j 个） |

## 各题的差异

| 题 | dp 的值 | 匹配时 | 不匹配时 |
|---|---|---|---|
| **LC-1143** LCS | 最长公共子序列长度 | `dp[i-1][j-1] + 1` | `max(dp[i-1][j], dp[i][j-1])` |
| **LC-0718** 最长公共**子数组** | 以 i、j 结尾的最长公共**连续**段 | `dp[i-1][j-1] + 1` | **`0`**（连续性断了！） |
| **LC-0115** Distinct Subsequences | t 在 s 中作为子序列出现的**次数** | `dp[i-1][j-1] + dp[i-1][j]` | `dp[i-1][j]` |
| **LC-0072** Edit Distance | 最少编辑次数 | `dp[i-1][j-1]` | `min(三个方向) + 1` |
| **LC-0010** 正则匹配 | 能否匹配 | 见下 | 见下 |
| **LC-0044** 通配符匹配 | 能否匹配 | 见下 | 见下 |

**LC-1143 vs LC-0718 的区别是本节最该记的一条**：
> **子序列不匹配时「继承」（取 max），子数组不匹配时「归零」。**
> 因为连续性一旦断了就必须从头开始。
> 而且 LC-0718 的答案是 `max(所有 dp[i][j])`，不是 `dp[m][n]`。

## LC-0010 vs LC-0044（必须分清）

| | LC-0010 正则 | LC-0044 通配符 |
|---|---|---|
| 单字符通配 | `.` | `?` |
| `*` 的含义 | **前一个字符**重复 0+ 次（`a*`、`.*`） | **自己**匹配任意序列 |
| `*` 能独立出现 | **不能** | **能** |
| 要看几个字符 | `p[j-1]` 和 `p[j-2]` | 只看 `p[j-1]` |
| 有贪心解法吗 | **没有** | **有**（O(1) 空间双指针） |

**LC-0044 的 `*` 转移只有两个分支**：
```python
dp[i][j] = dp[i][j-1]     # * 匹配空串
         or dp[i-1][j]    # * 再多吃一个 s 的字符
```

**LC-0010 的 `*` 要复杂一些**：
```python
dp[i][j] = dp[i][j-2]                                   # a* 匹配 0 次
         or (char_match(s[i-1], p[j-2]) and dp[i-1][j]) # a* 多吃一个
```

**两题的初始化都容易漏**：`dp[0][j]`（空的 s）只能被「能匹配空串的 p 前缀」匹配。
- LC-0044：`dp[0][j] = dp[0][j-1] and p[j-1] == '*'`
- LC-0010：`dp[0][j] = dp[0][j-2] if p[j-1] == '*' else False`

| **LC-3333** Find the Original Typed String II | 计数 DP + 前缀和优化 |

## 空间优化
双序列 DP 都只依赖**上一行**和**本行左边** ⟹ 可以滚动成一维 O(n)。
```python
prev = [...]                     # 上一行
for i in range(1, m + 1):
    cur = [...]
    for j in range(1, n + 1):
        cur[j] = ... prev[j-1] ... prev[j] ... cur[j-1] ...
    prev = cur
```
**想进一步压成一个数组**（原地滚动）就要手动保存 `dp[i-1][j-1]`（左上角那个值），
否则它会被本轮覆盖。这是双序列空间优化的经典坑。

## 复杂度
全部 **O(m·n)** 时间，O(n) 空间（滚动一行）。

## 常见错误
- LC-0718 不匹配时「继承」而不是归零；或者返回 `dp[m][n]` 而不是全局 max。
- LC-0091 漏掉 `'0'` 和前导零的处理。
- LC-0010 / LC-0044 的 `dp[0][j]` 初始化漏掉。
- LC-0044 里写出 `p[j-2]`（那是正则才需要的）。
- 一维滚动时没保存左上角的旧值。

## 复习时的 Pattern Recognition
> 「两个字符串之间的最优/计数」 → `dp[i][j]`，先写「字符匹配时」和「不匹配时」。
> 「把一个字符串切成若干段」 → `dp[i]` + 枚举最后一段。
> **子序列继承、子数组归零** —— 这一条分清了就不会错。
