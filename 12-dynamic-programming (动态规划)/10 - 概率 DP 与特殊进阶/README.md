# Level 1 · 10 概率 DP 与特殊进阶

## 核心定义
dp 存的是**概率**（或期望）而不是方案数 / 最优值。
转移从 `+=` 变成「**加权求和**」：每个来源乘上它发生的概率。

```python
dp[新状态] += dp[旧状态] * 该转移的概率
```

## 概率 DP 的四条通则

**① 初始概率是 1**
`dp[起点] = 1.0`（一定在起点）。

**② 每一步的概率之和应该是 1**（或者「流失掉的概率」有明确去处）
这是检查转移写对没有的最好办法。

**③ 不要在中途归一化**
直接累乘转移概率即可，最后再看要不要求和。

**④ 浮点精度**
题目一般允许 1e-5 ～ 1e-6 的误差。**不要用分数类，直接用 float**。
但要避免「大数减大数」这种损失精度的写法。

## 两个小节

### 01 - 离散概率转移

**LC-0688 Knight Probability in Chessboard**
`dp[step][r][c]` = 走了 step 步后**还在棋盘内**且停在 `(r,c)` 的概率。
每步 8 个方向，各 1/8：
```python
nxt[nr][nc] += dp[r][c] / 8      # 跳出棋盘的那部分概率就「流失」了
```
答案 = 所有格子概率之和。
**「流失」的概率就是跳出棋盘的概率** —— 这正好对应题意（跳出就结束且不算成功）。

**LC-0799 Champagne Tower**
不是严格的概率，但是同一个「流量分配」模型：
```python
overflow = (glass[i][j] - 1) / 2        # 超过 1 的部分平分给下面两个杯子
```
**关键**：杯子里的量要 `min(1, ...)`，溢出的才往下流。
**用「倒了多少」而不是「剩多少」来做 DP** —— 这个状态选择让转移变得线性。

### 02 - 停止过程与概率窗口优化

**LC-0837 New 21 Game**（本章最值得学的一题）
`dp[x]` = 从点数 x 出发，最终停在 `[k, n]` 内的概率。
```python
dp[x] = (dp[x+1] + dp[x+2] + ... + dp[x+maxPts]) / maxPts
```
朴素是 O(n · maxPts)。
**优化：那个求和是一个固定长度的滑动窗口** ⟹ 维护窗口和，O(1) 更新：
```python
window_sum += dp[x + 1] - dp[x + 1 + maxPts]      # 加新的、减出窗的
dp[x] = window_sum / maxPts
```
⟹ **O(n) 时间**。

> **「DP 转移里有一段连续求和」⟹ 用前缀和或滑动窗口把它降一维。**
> 这是 DP 优化里最常用的一招，不限于概率题。

**LC-0808 Soup Servings**
`dp[a][b]` = 剩 a 毫升 A 汤、b 毫升 B 汤时的答案，四种操作各 1/4。
**关键剪枝**：当 `n` 很大（> 4800）时答案趋近 1，直接返回 1.0 ——
不剪的话状态数是 O(n²/625) 会超时。
**「大 n 时答案收敛」这种剪枝要靠观察或打表发现**，是概率题的常见套路。

| 题 | 时间 | 空间 |

| LC-0688 | O(k · m · n) | O(m · n) |
| LC-0799 | O(rows²) | O(rows) |

| LC-0808 | O(n²/625)，大 n 剪枝后 O(1) | 同 |

## 常见错误
- 初始概率设成 0。
- 转移时忘了乘概率（当成计数 DP 做了）。
- LC-0799 没有 `min(1, ...)`（杯子装超过 1）。
- LC-0837 用朴素求和 ⟹ TLE。
- LC-0808 没做大 n 剪枝 ⟹ TLE / 栈溢出。
- 用 `==` 比较浮点数（应该比较 `abs(a-b) < eps`）。

## 为什么整章都是 P2
概率 DP 在 FAANG 面试里出现频率明显低于背包、双序列、状态机。
**但 LC-0837 的「滑动窗口优化 DP 转移」这个技巧值得单独记住** ——
它和概率无关，在任何「转移里有连续区间求和」的 DP 里都能用。
