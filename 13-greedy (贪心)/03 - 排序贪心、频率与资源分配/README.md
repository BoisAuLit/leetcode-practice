# Level 1 · 03 排序贪心、频率与资源分配

## 核心定义
> **排序把一个维度固定下来，剩下的就变成线性扫描或两端配对。**
> 本章的全部难点是：**该按什么排序？**

## 五个小节的排序键

| 小节 | 排序键 | 排完之后做什么 |
|---|---|---|
| 01 按收益/成本优先 | 单位收益降序 / 频率升序 | 线性拿 |
| 02 连续数字分组 | 值升序（或用频率表） | 从最小的开始成组消耗 |
| 03 排序差额 | **两个选项的差额** / 身高降序 | 取前 n 个 / 按下标插入 |
| 04 频率余数 MEX | 频率表 + 模运算 | 直接算 |
| 05 频率平衡 | 待交换元素升序 | 取前一半，`min(x, 2*全局最小)` |

## 01 - 按收益与成本优先级选择

### LC-1710 Maximum Units on a Truck
按**单位收益**（每箱装几个单位）降序，依次装满。
**为什么**：容量是统一的「箱位」，每箱占 1 个箱位 ⟹ 单位收益高的优先，典型的分数背包贪心。

### LC-1481 Least Number of Unique Integers after K Removals
按**频率升序**删。
**为什么**：要让「剩下的不同整数种类数」最少 ⟹ 应该**完整删掉**尽可能多的种类
⟹ 优先删频率最小的（代价最低）。

### LC-0881 Boats to Save People → **跨专题索引**
实体目录在 [02-two-pointers](<../../02-two-pointers (双指针)/01 - 对撞指针与贪心 (Opposite Ends)/01 - 经典对撞与贪心决策/04 - LC-0881 - Boats to Save People>)
（那里早就有，本次把补充解法并入了那份）。

它代表本章的另一个模式：**排序 + 两端配对**（最重的配最轻的）。
交换论证：若最优解里 H 和 X 同船、L 和 Y 同船，换成 (H,L) 和 (X,Y) 仍合法且船数不变。
**前提是每船最多 2 人** —— 3 人就变成装箱问题（NP-hard），贪心失效。

## 02 - 连续数字分组与 Frequency Map（LC-0846 Hand of Straights）

用频率表（或 `Counter` + 排序后的 key 列表）：
**每次从当前最小的还未用完的数开始**，往后取 `groupSize` 个连续数，各减 1。
不够就返回 False。

**为什么必须从最小的开始**：最小的数**只能**作为某个组的开头
（没有比它更小的数能带它）⟹ 它的归属是确定的，没有选择余地。
⟹ 贪心无需回溯。∎

## 03 - 排序差额与最小成本分配（本章最该掌握的两道）

### LC-1029 Two City Scheduling —— **按差额排序**
```python
costs.sort(key=lambda c: c[0] - c[1])     # 去 A 比去 B 省多少
前 n 个去 A，后 n 个去 B
```
**交换论证**：若最优解里 `diff[i] < diff[j]` 但 i 去 B、j 去 A，互换后变化是
`diff[i] - diff[j] < 0` ⟹ 更便宜 ⟹ 矛盾。∎

**等价视角**：先假设全去 B（基准 `sum(b)`），再挑 n 个「改去 A」，
每人额外代价 `a[i] - b[i]` ⟹ 挑最小的 n 个。这个视角更容易推广到「配额不是一半」。

> **「二选一 + 固定配额」⟹ 按两个选项的差额排序。**

### LC-0406 Queue Reconstruction by Height —— **排序 + 按下标插入**
```python
people.sort(key=lambda p: (-p[0], p[1]))   # 身高降序；同高时 k 升序
for h, k in people: res.insert(k, [h, k])
```
**为什么正确**：从最高的开始放，已放进去的**都不比他矮**
⟹ 他的 k（前面有几个 ≥ 他的）**恰好就是他该占的下标**。
而后来插入的人都比他矮（不计入他的 k）⟹ **一旦放好就不会被破坏**。∎

**为什么同高时 k 要升序**：同身高的人互相计数，k 小的必须在前；
k 降序的话先插的会被后插的挤到后面，位置就错了。

**不能反过来按身高升序排** —— 那样「已放好的人」比当前的人矮，k 和下标就没有对应关系了。

## 04 - 频率、余数与 MEX（LC-2598）

操作是「每个数 ±value」⟹ 每个数在**模 value** 的同余类里可以任意移动。
所以只需要统计每个余数类有多少个数，然后找最小的 **MEX**
（第一个「这个余数类的数不够用」的位置）。
**把问题从数值搬到余数类上** 是这题唯一的洞察。

## 05 - 频率平衡与最小交换代价（LC-2561 Rearranging Fruits）

三步：
1. **可行性**：某种水果总数为奇数 ⟹ -1。否则每篮各应有一半。
2. **配对**：把两篮各自多余的元素合起来排序，**代价 = 前一半之和**
   （后一半搭车，因为代价只取 `min`）。
3. **「借最小值」**：每一对的实际代价是 **`min(min(a,b), 2 * 全局最小)`** ——
   可以用全局最小的水果当中转（换两次），有时比直接换便宜。

**漏掉 `2 * m` 这一项是本题最常见的错解。**

## 复杂度
全部 **O(n log n)**（排序主导），LC-0406 是 O(n²)（`list.insert`）。
**报复杂度时不要只说扫描那部分，排序那一项不能省。**

## 常见错误
- LC-1481 按频率降序删（应该升序）。
- LC-0846 不从最小的数开始成组。
- LC-1029 按绝对花费排序而不是差额。
- LC-0406 按身高升序排，或同高时 k 降序。
- LC-2561 漏掉「借全局最小值中转」的 `2 * m`。
- LC-0881 以为每船可以超过 2 人。

## 复习时的 Pattern Recognition
> 「按某个标准优先选」「恰好各选一半」「两两配对」「分成连续的组」
> → 排序贪心。**先想清楚排序键，再写扫描。**
> 排完序之后是**单向扫描**还是**两端配对**？
