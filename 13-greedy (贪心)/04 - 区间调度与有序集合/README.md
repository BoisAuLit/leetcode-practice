# Level 1 · 04 区间调度与有序集合

## 核心定义
事件带**时间**属性，而且「现在怎么选」会影响「以后还能选什么」。
需要一个**有序结构**（堆 / 有序集合）来动态维护候选。

## 01 - 最早截止时间优先（LC-1353 Maximum Events）

**策略**：每天参加「所有当前可参加的会议里，**结束最早**的那个」。
这就是经典的 **Earliest Deadline First (EDF)**。

**为什么**：结束早的会议机会窗口最窄，再不参加就过期了；结束晚的以后还有机会。

实现：按 start 排序入堆（堆里存 **end**），每天先清掉 `end < day` 的过期会议，再弹一个。

> ### ⚠️ 这**不是**区间调度（LC-0435 那种）
> | | 区间调度（LC-0435 / LC-0452） | LC-1353 本题 |
> |---|---|---|
> | 占用 | **整个区间** | **只占一天** |
> | 解法 | 按 **end 排序** + 线性贪心 | **堆**动态维护可选集合 |
> | 为什么 | 选了就霸占整段，没有后续选择 | 同一个会议可以等到区间里任意一天再参加 |
>
> **把两者搞混是这道题最常见的错误。**
> LC-0435 / LC-0452 的主归属在 [14-intervals](<../../14-intervals (区间)/>)。

**跨专题**：LC-1353 的实体目录在本专题，
[09-heap 的 `05/02`](<../../09-heap (堆)/05 - Heap + Scheduling 任务调度/02 - 动态任务与事件优先级/README.md>) 只建索引
—— 它的 Primary Pattern 是 Greedy（EDF），堆只是用来快速拿到「结束最早的那个」。

## 02 - 带时间约束的资源分配（LC-1488 Avoid Flood in The City）

**问题**：下雨会让湖满，晴天可以抽干**一个**湖。要避免任何湖二次积水。

**策略**：
- 用一个 **有序集合 / 列表**记录「到目前为止所有晴天的日期」。
- 每当某个湖**第二次**下雨时，必须在「它上次下雨之后」的晴天里抽干它
  ⟹ 用**二分**找「大于上次下雨日期的最小晴天」。
- 找不到 ⟹ 返回 `[]`（无解）。
- **找到的那个晴天要从集合里删掉**（已被占用）。

**为什么选「最早的那个可用晴天」**（交换论证）：
晚一点的晴天「更通用」—— 它能给更多后续的湖用。
所以应该用最早的那个，把晚的留给后面。∎
（又是本专题的核心直觉：**优先消耗更不通用的资源**，见 Level 1 `02`。）

**实现选择**：
| 结构 | 查找 | 删除 | 适用 |
|---|---|---|---|
| `sortedcontainers.SortedList` | O(log n) | O(log n) | 最优，但是第三方库 |
| 有序 list + `bisect` | O(log n) | **O(n)**（list.pop） | 标准库能做，n ≤ 10⁵ 勉强 |
| 堆 + 惰性删除 | — | — | 不适合（需要「大于某值的最小元素」，堆给不了） |

> **堆做不到「找大于 x 的最小元素」** —— 这正是 Level 1 `04` 需要「有序集合」而不是堆的原因。
> 对照 [09-heap 的 LC-2817](<../../09-heap (堆)/07 - 跨专题与低优先级存档/README.md>)：那里也是同一个结论。

## 题目

| # | 题 | 优先级 | 核心结构 |
|---|---|---|---|
| 01/01 | LC-1353 Maximum Number of Events That Can Be Attended | P1 | 堆（EDF） |
| 02/01 | LC-1488 Avoid Flood in The City | P2 | **有序集合 + 二分** |

## 复杂度
- LC-1353：O(n log n + D log n)（有天数跳跃时接近 O(n log n)）
- LC-1488：O(n log n)（用 SortedList）/ O(n²) 最坏（用 list + bisect）

## 常见错误
- LC-1353 套用区间调度的「按 end 排序 + 线性贪心」。
- LC-1353 忘了清理堆顶的过期会议。
- LC-1488 用堆而不是有序集合（堆取不到「大于 x 的最小元素」）。
- LC-1488 用了晴天却忘了把它从集合里删掉。
- LC-1488 挑了最晚的那个可用晴天（应该挑最早的）。

## 复习时的 Pattern Recognition
> 「每个时间点只能做一件事，每个任务有截止期」 → **EDF**（堆里存 deadline）。
> 「需要找『大于某个时刻的最早可用资源』」 → **有序集合 + 二分**，不是堆。
