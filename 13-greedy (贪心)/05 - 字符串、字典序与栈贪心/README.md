# Level 1 · 05 字符串、字典序与栈贪心

## 核心定义
字符串贪心的两个主题：
- **「最后出现位置」/「可行性区间」** —— 一次扫描维护边界。
- **字典序最优** —— 贪心单调栈：能让高位变小就换，但必须保证后续仍可行。

## 01 - 字符最后出现位置与最少分区（LC-0763 Partition Labels）

```python
last = {c: i for i, c in enumerate(s)}     # 每个字符最后出现的位置
end = 0
for i, c in enumerate(s):
    end = max(end, last[c])
    if i == end:                            # 当前区间里所有字符都在区间内
        切一刀
```

**为什么 `i == end` 就能切**：`end` 是「当前区间里所有字符的最后出现位置的最大值」。
走到 `i == end` 说明这段里的每个字符都不会再出现在后面 ⟹ **可以安全切断**。
而且因为我们一直在扩展 `end`，这是**最早能切的位置** ⟹ 分区数最少。∎

> 这个「维护当前区间必须延伸到哪里」的套法和 LC-0045 的 `curr_end` 是同一个形状。

## 02 - 括号可行性区间（LC-0678 Valid Parenthesis String）

`*` 可以当 `(`、`)` 或空 ⟹ 未匹配左括号的数量不是一个值，而是一个**区间** `[lo, hi]`：

```python
lo = hi = 0
for c in s:
    if c == '(':   lo += 1; hi += 1
    elif c == ')': lo -= 1; hi -= 1
    else:          lo -= 1; hi += 1        # '*' 可以是 ')' 或 '('
    if hi < 0: return False                # 连最乐观的情况都不够左括号
    lo = max(lo, 0)                        # ★ lo 不能为负
return lo == 0
```

**两个关键点**：
- **`hi < 0` 就立刻失败**：`hi` 是最乐观的未匹配左括号数，连它都负了就无救。
- **`lo = max(lo, 0)`**：未匹配左括号数不可能是负数 ——
  如果算出负数，说明我们把某些 `*` 当成 `)` 用多了，应该把它们当成空。
  **不 clamp 的话结果会偏小，`"(*)"`这类用例就会错。**

**答案是 `lo == 0`**：存在一种 `*` 的赋值让左右恰好匹配。

> **「可行性区间」这个技巧**在很多「有通配/可选项」的题里都能用 ——
> 维护一个 `[最少, 最多]` 区间而不是单个值。

## 03 - 最优数字与自定义比较规则

### LC-0670 Maximum Swap
**最多交换一次**，求最大数。
策略：从右往左记录「右边最大数字及其位置」，从左往右找**第一个**比右边某个数字小的位置，
和右边**最大且最靠右**的那个交换。
**「最靠右」很关键**：相同数字要选最右边的那个，这样换完高位增益最大。

### LC-0179 Largest Number —— **自定义比较规则**
```python
nums.sort(key=cmp_to_key(lambda a, b: 1 if a + b < b + a else -1))
```
**比较的是拼接结果**：`a` 该排在 `b` 前面 ⟺ `a + b > b + a`（字符串比较）。
例：`"3"` vs `"30"` ⟹ `"330" > "303"` ⟹ 3 排前面。

**为什么这个比较是一个合法的全序**（可以排序）：需要验证传递性 ——
`a+b >= b+a` 且 `b+c >= c+b` ⟹ `a+c >= c+a`。这是可以证明的，所以排序合法。
**不能用「按首位降序」之类的简化规则** —— `"3"` 和 `"30"` 首位相同就分不出来了。

**收尾**：结果可能是 `"000"` ⟹ 要处理成 `"0"`。

## 04 - Stack 与字典序最优化

### LC-3170 Lexicographically Minimum String After Removing Stars
每个 `*` 删掉它左边**最小**的字符（有多个最小的就删**最靠右**的那个）。
用 26 个栈（每个字母一个栈，存下标），遇到 `*` 就找最小的非空字母栈，弹出它的栈顶（最右的）。

**为什么要删「最靠右」的那个**：删掉靠右的，留下的字符相对顺序让结果字典序更小。

### LC-2434 Using a Robot to Print the Lexicographically Smallest String
两个栈（原串 + 临时栈 t）。
**每一步**：如果 t 的栈顶 **<= 原串剩余部分的最小字符**，就输出 t 的栈顶；否则把下一个字符压进 t。
需要预处理**后缀最小字符**数组。

**为什么**：输出 t 栈顶是「现在就确定一位」，压栈是「推迟决定」。
只有当栈顶已经不可能被更小的字符超越时，输出它才不后悔。

> **这一节和 [18-monotonic 的 LC-0402 / 0316 / 1673](<../../18-monotonic-fuck-you (单调栈、单调队列)/03 - 单调栈与贪心构造/README.md>) 是同一个骨架**：
> ```python
> while stack and stack[-1] > x and <可行性条件>: stack.pop()
> ```
> **区别只在「可行性条件」是什么**：
> | 题 | 可行性条件 |
> |---|---|
> | LC-0402 | `k > 0`（删除预算） |
> | LC-0316 | 弹掉的字符以后还会出现 |
> | LC-1673 | 后面还够补满 k 个 |
> | LC-2434 | 栈顶 <= 剩余部分的最小字符 |

## 05 - 特殊递归分解（LC-0761 Special Binary String）

把串递归分解成若干「平衡块」（每块都是一个 special string），
对每块**递归处理内部**，然后把这些块按**字典序降序**拼接。

**为什么降序**：大的块放前面字典序更大（`"1...0"` 开头的块本身就更"重"）。
这是一个「**递归 + 局部排序**」的组合，在本专题里是孤例，标 P2。

## 常见错误
- LC-0678 忘了 `lo = max(lo, 0)`。
- LC-0678 用一个计数器而不是区间（`*` 的三义性处理不了）。
- LC-0763 用「字符第一次出现」而不是**最后一次**。
- LC-0179 用「按首位降序」之类的简化比较规则。
- LC-0179 忘了处理全 0 的结果。
- LC-0670 交换时选了最左边的那个最大数字（应该选最右的）。
- LC-3170 删掉了最左边的最小字符（应该删最右的）。

## 复习时的 Pattern Recognition
> 「最少分成几段使字符不跨段」 → 维护「当前段必须延伸到哪」。
> 「有通配符的可行性」 → 维护 `[最少, 最多]` **区间**。
> 「字典序最小/最大」 → 贪心单调栈，**先想清楚「什么时候允许 Pop」**。
> 「拼接出最大数」 → 自定义比较规则（比较 `a+b` 和 `b+a`）。
