# 13 · Greedy（贪心）

> 贪心题的难点**从来不是代码**，而是两个问题：
> ## **① 该按什么排序 / 优先选谁？② 为什么这样选是最优的？**
>
> 本专题每道题的 solution.py 里都写了**交换论证**或等价说明。
> **写不出证明的贪心，往往就是错的** —— 这时该考虑 DP。

本专题共 **28 道正式题**（+ 2 个「变体 · …」归档目录，不参与复习队列），6 个 Level 1。

## 一、贪心的三种常见形态

| 形态 | 做法 | 本专题例子 |
|---|---|---|
| **维护可达边界** | 一路扫描，记住「目前最远能到哪」，不够就付代价 | LC-0055、LC-0045、LC-1024、**LC-0330** |
| **排序后扫描 / 配对** | 先排序把一个维度固定，再线性扫或两端配对 | LC-1710、LC-0846、LC-1029、LC-0881、LC-0406 |
| **维护资源状态** | 每步做局部决策，优先消耗「更不通用」的资源 | LC-0134、LC-0860、LC-0135、LC-0678 |

## 三、本专题最该记住的五条

**① 「维护可达边界」是一个骨架，不是四道题**

| 题 | reach 的含义 | 不够时怎么办 |
|---|---|---|
| LC-0055 | 能走到的最远下标 | 返回 False |
| LC-0045 | 同上，但要**分层** | 再跳一次（`jumps += 1`） |
| LC-1024 | 片段能覆盖到的最右端 | 再用一个片段，覆盖不到就 -1 |
| **LC-0330** | 能表示出的**最大整数** | **补 `reach+1`，范围翻倍** |

**LC-0330 把这个骨架搬到了数值上**，是最能说明「贪心本质是维护可达边界」的一题。

**② 「二选一 + 固定配额」⟹ 按差额排序**
LC-1029 Two City Scheduling：按 `cost[0] - cost[1]` 排序，前 n 个去 A。
交换论证：两人互换的收益差恰好是 `diff[i] - diff[j]`。

**③ 「优先消耗更不通用的资源」**
LC-0860 付 20 时优先用 `10 + 5` 而不是 `5+5+5` ——
因为 10 元只能给付 20 的人找零，而 5 元两种人都能找。

**④ 「双向约束 ⟹ 正反各扫一遍再取 max」**
LC-0135 Candy：左扫一遍满足左约束、右扫一遍满足右约束、取 max 同时满足两者。
同样的模式见 LC-0042（前后缀最大值取 min）、LC-0238（前后缀积相乘）。

**⑤ 字典序最优 ⟹ 贪心单调栈**
LC-2434、LC-3170 的「能弹就弹到字典序更小」和
[18-monotonic 的 LC-0402 / 0316 / 1673](<../18-monotonic-fuck-you (单调栈、单调队列)/03 - 单调栈与贪心构造/README.md>)
是同一个骨架，**区别只在「什么时候允许 Pop」这个可行性条件**。

## 四、什么时候贪心会**错**

| 情况 | 该用什么 | 例子 |
|---|---|---|
| 每组可以超过 2 个元素 | DP / 搜索（装箱是 NP-hard） | LC-0881 只因为「每船最多 2 人」才能贪心 |
| 操作顺序影响后续代价 | **区间 DP** | LC-0312、LC-1547（见 [12-DP](<../12-dynamic-programming (动态规划)/08 - 区间 DP 与博弈/README.md>)） |
| 加了次数 / 冷却 / 费用限制 | **状态机 DP** | LC-0122 贪心对，但 LC-0123 / 0309 / 0714 **全都不对** |
| 需要「所有方案」 | 回溯 | 见 [10-backtracking](<../10-backtracking (回溯)/README.md>) |

**LC-0122 是最好的警示**：无限次交易时「所有上涨差之和」这个贪心是对的，
但一旦加任何限制就不成立。**不要把一道题的贪心结论推广到整个系列。**
