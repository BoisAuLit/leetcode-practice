# LC 2021 · Brightest Position on Street · 双数组最优解

## 题意

数轴上有一排路灯,`lights[i] = [position, range]` 表示这盏灯照亮 `[position - range, position + range]`(两端都包含)。某个位置的 **亮度 (brightness)** = 有几盏灯照到它。求 **最亮的位置**,有多个就取 **最小** 的。

- `1 <= lights.length <= 10^5`
- `-10^8 <= position <= 10^8`,`0 <= range <= 10^8`

坐标范围太大,不能一格一格去数。

## 最优解代码

```python
class Solution:
    def brightestPosition(self, lights: list[list[int]]) -> int:
        arrL = []
        arrR = []
        for pos, radius in lights:
            arrL.append(pos - radius)      # 每盏灯的左端点(开灯的位置)
            arrR.append(pos + radius)      # 每盏灯的右端点(最后一个还亮的位置)

        arrL.sort()                        # 两个数组各自独立排序,不需要配对
        arrR.sort()

        p = 0                              # 指向 arrR 里第一个还没被减掉的右端点
        score = 0                          # 当前左端点 L 处的亮度
        bestScore = 0
        bestL = arrL[0]

        for i in range(len(arrL)):
            L = arrL[i]
            score += 1                     # ① 又多了一盏"左端点 <= L"的灯

            while p < len(arrR) and arrR[p] < L:
                score -= 1                 # ② 这盏灯在 L 之前就结束了,减掉
                p += 1

            if score > bestScore:          # 严格大于 → 并列时保留最小的 L
                bestScore = score
                bestL = L

        return bestL
```

时间 O(n log n)(两次排序),空间 O(n)。

## 原理一:答案一定是某盏灯的左端点

沿着数轴从左往右走,亮度什么时候会 **变大**?只有在 **进入某盏灯** 的时候,也就是某个 `pos - range` 处。走出灯光只会让亮度变小。

所以"最大亮度第一次出现的位置"必然是某盏灯的左端点。**候选答案只有 n 个:所有的 `L = pos - range`**,其他位置根本不用看。

问题就变成:**对每一个左端点 L,算出 L 处的亮度,取最大(并列取最小 L)。**

## 原理二:L 处的亮度怎么算(减法的来历)

一盏灯 `[l, r]` 照到 L,要同时满足两件事:

1. `l <= L`:到 L 这个位置时,这盏灯 **已经开了**
2. `r >= L`:到 L 这个位置时,这盏灯 **还没关**

把这两个条件 **拆开数**:

- 先只管第 1 条,把"已经开了"的灯全部拿出来,记作 ①:`左端点 <= L 的灯数`。
- 这一堆里混着两种灯:**还亮着的**,和 **开过但已经关了的**(`r < L`)。
- 把"已经关了"的挑出去,记作 ②:`右端点 < L 的灯数`。
- 剩下的就是"开了而且还没关"的,正好是照着 L 的灯。

```
L 处的亮度 = ① − ② = (左端点 <= L 的灯数) − (右端点 < L 的灯数)
```

**为什么不会减多**:一盏灯要先开才能关。`r < L` 的灯,它的 `l` 肯定也 `< L`,所以它一定在 ① 里。② 永远是 ① 的子集,减的时候不会减到 ① 以外的灯。

### 用例 1 对照

`lights = [[-3,2],[1,2],[3,3]]`,三盏灯照亮 `[-5,-1]`、`[-1,3]`、`[0,6]`。

```
arrL = [-5, -1, 0]        arrR = [-1, 3, 6]
```

| L | ① 左端点 <= L | ② 右端点 < L | 亮度 ① − ② | 直接数 |
|---|---|---|---|---|
| -5 | 1 (红) | 0 | 1 | 红 → 1 |
| -1 | 2 (红、绿) | 0 | **2** | 红、绿 → 2 |
| 0 | 3 (红、绿、蓝) | 1 (红,r=-1 < 0) | 2 | 绿、蓝 → 2 |

最大亮度 2,第一次出现在 L = -1,答案 -1。

## 原理三:为什么左右端点可以各自独立排序

① 和 ② 都只是在 **数个数**:"有几盏灯的左端点 <= L"、"有几盏灯的右端点 < L"。这两个问题都 **不需要知道哪个左端点和哪个右端点属于同一盏灯**。

所以可以把所有左端点排成一列、所有右端点另排一列,各自独立排序,再各自用指针去数。把配对关系拆散,对结果没有任何影响。这是这个解法最巧的地方。

## 代码逐行对照

| 代码 | 在做什么 |
|---|---|
| `arrL.sort(); arrR.sort()` | 两个数组各自排序,之后用两个指针同步扫 |
| `for i in range(len(arrL))` | 按从小到大的顺序看每个候选位置 `L = arrL[i]` |
| `score += 1` | 走到第 i 个左端点时,`arrL[0..i]` 全部 `<= L`,所以 ① = i + 1;这行就是在维护 ① |
| `while p < len(arrR) and arrR[p] < L` | `arrR` 已排序,`p` 指向第一个还没减掉的右端点;只要它 `< L`,这盏灯在 L 之前就结束了 |
| `score -= 1; p += 1` | 减掉 ②;`p` 只前进不回头,整个循环总共最多走 n 步 |
| `if score > bestScore` | 严格大于,保证并列时留最小的 L |

执行完 `+1` 和 `while` 之后,`score` 正好等于 `① − ②`,也就是 L 处的亮度。

## 两个细节

- **`score += 1` 放在 `while` 之前还是之后都对**:`while` 减的是"右端点 < L"的灯,和这次新加的灯互不影响。
- **`arrL` 里有重复值时**(两盏灯左端点相同):第一次到这个 L 时 `score` 少算了 1,第二次才算全。但两次记录的 `bestL` 是同一个坐标,结果不受影响。

## 为什么比差分字典版快

三个版本都是 O(n log n),差距在常数(10^5 盏灯实测):

| 版本 | 耗时 | 慢在哪 |
|---|---|---|
| 字典差分 `defaultdict` + `sorted(d.items())` | 0.163 s | 哈希插入 + 排序 2n 个 **元组** |
| 事件列表 `(坐标, ±1)` 排序 | 0.125 s | 排序 2n 个元组 |
| 双数组(本解法) | **0.059 s** | 只排两个 **纯整数** 列表 |

Python 对纯整数列表的排序有专门优化,比较整数比比较元组便宜很多;双数组版没有任何元组和哈希。**字典版慢在"元组 + 哈希",双数组版快在"只排整数"。**

## 和扫描线的关系

| | 扫描线 / 差分 | 双数组 |
|---|---|---|
| 看哪些位置 | 所有事件点(左端点、右端点 + 1) | 只看左端点 |
| 怎么算亮度 | 前缀和一路累加 | 左端点计数 − 右端点计数 |
| 排序对象 | 元组 `(坐标, ±1)` | 两个整数数组 |
| 适用范围 | 更通用(任何"区间 → 每个位置的值"的题) | 只适用于"求最大重叠处"这类只需看左端点的题 |

扫描线是通用武器;双数组是针对"求最大重叠"的专用快枪。同一个技巧也是 LC 253 Meeting Rooms II(最多同时几场会议)的标准解法。

## 一句话记忆

**亮度只在进灯时增加,所以最亮处一定是某个左端点。L 处亮度 = 左端点 ≤ L 的数量 − 右端点 < L 的数量("开过的" 减 "已经关了的"),两边各自排序、各自计数,不用配对。**
