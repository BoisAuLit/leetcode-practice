# Interval Algorithm Comparison Table（区间算法对照表）

> 区间题看起来都是「排序 + 扫一遍」，但**优化目标完全不同** ——
> 目标决定排序键，排序键决定不等号。先问目标，再写代码。

---

## 一、四个最容易混淆的目标

| 题 | 优化目标 | 排序键 | 扫描时维护什么 | 答案是什么 |
|---|---|---|---|---|
| [LC-0056 Merge Intervals](<../01 - 区间合并、插入与范围整理/01 - 标准区间合并与插入/01 - LC-0056 - Merge Intervals>) | 求**并集（Union）** | **start 升序** | 当前合并段的右端点 `cur_end` | 合并后的区间列表 |
| [LC-0435 Non-overlapping](<../03 - 不重叠区间与贪心调度/01 - 冲突检测与最大兼容区间数量/02 - LC-0435 - Non-overlapping Intervals>) | **最大化**互不相交区间数 | **end 升序** | 上一个保留区间的 end | 要删除的个数 `n - kept` |
| [LC-0452 Minimum Arrows](<../03 - 不重叠区间与贪心调度/02 - 最少覆盖点与区间射击/01 - LC-0452 - Minimum Number of Arrows to Burst Balloons>) | **最小化**覆盖所有区间的点数 | **end 升序** | 当前箭的位置 `arrow_x` | 箭数 |
| [LC-0253 Meeting Rooms II](<../04 - 重叠计数、扫描线与资源分配/01 - 最少会议室与最大并发数/01 - LC-0253 - Meeting Rooms II>) | 求**最大并发数（Max Overlap）** | **start 升序** + 堆 | 各房间的结束时间（最小堆） | 堆的最大尺寸 |

**关键认识**：
- **LC-0435 和 LC-0452 是同一个贪心的两种计数方式。**
  「最多能选出 k 个互不重叠的区间」⟺「需要 k 支箭」。
  `kept = max_non_overlapping`，`arrows = kept`，`removals = n - kept`。
- **LC-0056 和 LC-0253 都按 start 排序，但一个要并集、一个要并发数**，
  完全不能互相代入。
- **排序键选错是这四题唯一的失败模式**：
  用 start 排序做 LC-0435 会错（`[[1,100],[2,3],[3,4]]` 会保留 `[1,100]` 而只得 1，
  正确答案是保留 `[2,3],[3,4]` 得 2）。

## 二、九个模板的总索引

| # | 模板 | 核心代码 | 时间 | 空间 | 代表题 |
|---|---|---|---|---|---|
| 1 | **Sort + Merge** | `start > cur_end ? 新段 : cur_end = max(...)` | O(n log n) | O(n) 输出 | LC-0056, LC-0759 |
| 2 | **Insert Interval（三段式）** | 左边原样 → 合并相交 → 右边原样 | **O(n)**（已排序！） | O(n) | LC-0057, LC-1272 |
| 3 | **Two-pointer Intersection** | `max(s)` / `min(e)`，弹 end 更小的 | **O(m+n)** | O(1) | LC-0986, LC-1229 |
| 4 | **End-time Greedy** | 按 end 排序，`start > last_end` 才取 | O(n log n) | O(1) | LC-0435, LC-0452, LC-0252 |
| 5 | **Min Heap（Meeting Rooms）** | 堆存结束时间，能复用就 `heapreplace` | O(n log n) | O(n) | LC-0253, LC-2406 |
| 6 | **Sweep Line（事件排序）** | `(pos, ±1)` 排序后扫，tie-break 决定语义 | O(n log n) | O(n) | LC-0253, LC-2021, LC-0759 |
| 7 | **Difference Array + 前缀和** | `diff[l]+=v; diff[r(+1)]-=v`，一次 accumulate | **O(n + V)** | O(V) | LC-1094, LC-1109, LC-2021 |
| 8 | **Offline Query + Min Heap** | 查询排序 + 区间排序 + 懒删除堆 | O((n+q) log n) | O(n) | LC-1851 |
| 9 | **Dynamic Booking** | 在线维护已接受区间，冲突即拒 | 单次 O(n)（列表）/ O(log n)（平衡树） | O(n) | LC-0729, LC-0731 |

> ⚠️ **不要把所有题都写成 O(n log n)。**
> - 模板 2（Insert Interval）输入**已排序** ⟹ **O(n)**，不要排序。
> - 模板 3（Two Pointers）输入已排序 ⟹ **O(m+n)**；LC-1229 不保证有序，才要 O(m log m + n log n)。
> - 模板 7（差分数组）吃值域 ⟹ **O(n + V)**，V 小时比排序快。
> - 模板 8 要分开算 `n` 个区间和 `q` 个查询 ⟹ **O((n+q) log n)**，不是 O(n log n)。
> - 模板 9 用 Python `list` + `bisect`：查找 O(log n) 但 `insert` 搬移 **O(n)**
>   ⟹ 单次仍是 O(n)。**调了 bisect 不等于 O(log n) 插入。**

## 三、哪些题共享同一个核心模板

### 完全同一套代码，只改比较条件

| 组 | 题 | 差别 |
|---|---|---|
| 合并类 | LC-0056 / LC-0759 | 759 = 56 + 取相邻段之间的 Gap |
| 端点贪心 | LC-0435 / LC-0452 / LC-0252 | 252 只问有没有冲突；435 数个数；452 数点数 |
| 并发数 | LC-0253 / LC-2406 | **端点语义不同**：半开 `<=` vs 闭 `<` |
| 差分数组 | LC-1094 / LC-1109 / LC-2021 | 1094 要峰值；1109 要整条数组；2021 要 argmax |
| 双指针交集 | LC-0986 / LC-1229 | 1229 多一个长度过滤 + 要先排序 |
| 在线预订 | LC-0729 / LC-0731 | 731 多维护一层 `overlaps` 列表 |
| 区间代数 | LC-0057 / LC-1272 | 57 是加（会合并）；1272 是减（会裂成两段） |

### 必须更换优化目标（不能互相代入）

- **并集** vs **最大并发数**：LC-0056 ↔ LC-0253
- **最大化保留** vs **最小化点数**：LC-0435 ↔ LC-0452（虽然答案数值相同，目标语义不同）
- **区间的交集** vs **空闲的交集**：LC-0986 ↔ LC-0759（759 要先转成「忙碌的并集」）

### 哪些题必须用 Heap

| 题 | 为什么非 Heap 不可 | 能否换掉 |
|---|---|---|
| LC-0253 | 要知道**哪个房间**最早空出来 | 可以换成扫描线/差分（只要最大并发数） |
| LC-2406 | 同上 | 同上 |
| LC-1851 | 要在**一堆活动区间**里取**最短**的 | ❌ 不好换 —— 这是 Heap 的本质用法 |
| LC-0759（解法 B） | k 条流取最小队头 | 可以换成 Flatten + Sort |

**只需要 Sorting + Scan 的**：LC-0056、LC-0057、LC-0435、LC-0452、LC-0252、
LC-1288、LC-0228、LC-0163、LC-1272、LC-0986、LC-1229。

**需要对 Query 离线排序的**：LC-1851（唯一一道）。

**应当用真正的动态区间数据结构的**：
LC-0729 / LC-0731 的升级版（`sortedcontainers.SortedList` / 红黑树 / 动态开点线段树），
以及 LC-0732 My Calendar III、LC-2276 Count Integers in Intervals（见 Future Candidates）。
本专题的题目规模（`n <= 1000`）用 O(n) 单次检查就够，不必上重型结构。

## 四、常见错误贪心策略 + 反例

| 题 | 错误策略 | 反例 | 为什么错 |
|---|---|---|---|
| LC-0435 | 按 **start** 升序保留 | `[[1,100],[2,3],[3,4]]` → 得 1，正确 2 | 先占的区间可能特别长，挤掉后面很多个 |
| LC-0435 | 按**区间长度**升序保留 | `[[1,2],[2,3],[1,3]]` 的变体会失败 | 短区间的位置可能很差 |
| LC-0452 | 每次射「能扎破最多气球」的点 | `[[2,4],[2,2],[5,7],[4,7],[3,7]]` → 得 3，正确 2 | **最大覆盖贪心对集合覆盖只有 O(log n) 近似**，不最优 |
| LC-0056 | 排序后只比较相邻区间的 end | `[[1,10],[2,3],[4,5]]` | 必须维护 `cur_end = max(...)`，否则嵌套区间会把右界缩回去 |
| LC-1288 | 排序 tie-break 用 `(start, end 升序)` | `[[1,4],[1,2]]` → 得 2，正确 1 | 同起点时长的必须在前，短的才会被判为被覆盖 |
| LC-0253 | 对 start / end 分别排序后直接相减 | — | 必须双指针同步扫，不能只看总数 |
| LC-0759 | 去求「所有人空闲区间的交集」 | — | 方向错了，应求「忙碌的并集」再取 Gap（德摩根律） |
| LC-1094 | 事件排序不做 tie-break | `[[2,1,5],[3,5,7]]`, cap 3 | 同一站必须先下车再上车，否则虚高误判超载 |

## 五、复杂度速查（按实际操作数算，不要一律写 O(n log n)）

| 题 | 时间 | 空间 | 瓶颈 |
|---|---|---|---|
| LC-0056 | O(n log n) | O(n) | 排序 |
| LC-0057 | **O(n)** | O(n) | 输入已排序，只扫一遍 |
| LC-0228 / LC-0163 | **O(n)** | O(n) | 输入已排序 |
| LC-1288 | O(n log n) | O(1) 额外 | 排序 |
| LC-1272 | **O(n)** | O(n) 输出 | 输入已排序 |
| LC-0986 | **O(m + n)** | O(1) 额外 | 双指针 |
| LC-1229 | O(m log m + n log n) | O(1) 额外 | **排序（题目不保证有序）** |
| LC-0759 | 解法 A O(N log N) / 解法 B **O(N log k)** | O(N) / **O(k)** | 排序 vs 堆（k = 员工数） |
| LC-0252 | O(n log n) | O(1) | 排序 |
| LC-0435 / LC-0452 | O(n log n) | O(1) | 排序 |
| LC-0253 | O(n log n) | O(n) | 排序 + n 次堆操作 |
| LC-2406 | 差分 **O(n + V)** / 堆 O(n log n) | O(V) / O(n) | V = 1e6 |
| LC-1094 | **O(n + V)** | O(V) | V = 1001 |
| LC-1109 | **O(n + m)** | O(n) | 一次前缀和（m = bookings 数） |
| LC-2021 | **O(n + V)** 或 O(n log n) | O(n) | 差分 / 事件排序 |
| LC-1851 | **O((n + q) log n)** | O(n + q) | n 个区间 + q 个查询各自排序 + 堆 |
| LC-0729 | 单次 **O(n)**，共 O(n²) | O(n) | 线性扫描（平衡树可降到 O(n log n)） |
| LC-0731 | 单次 **O(n)**，共 O(n²) | O(n²) 最坏 | overlaps 列表 |
