# 整数溢出与数值陷阱（Overflow & Numeric Pitfalls）

> Python 的 `int` 是任意精度的，所以**溢出不会自动发生** ——
> 这既是好事（不会算错），也是坏事（题目的范围限制必须你自己检查）。
> 这份文档把本专题所有数值陷阱集中在一处。

---

## 一、Python 的 `//` 和 `%` 对负数是**向下取整**

| 表达式 | Python | C / C++ / Java | 差异来源 |
|---|---|---|---|
| `-7 // 2` | **`-4`** | `-3` | Python 向 **-∞** 取整；C 向 **0** 截断 |
| `-7 % 2` | **`1`** | `-1` | Python 结果符号跟**除数**；C 跟**被除数** |
| `-123 // 10` | **`-13`** | `-12` | 同上 |
| `-123 % 10` | **`7`** | `-3` | 同上 |

**后果**：正数的拆位逻辑**不能**直接套到负数上。
`-123 % 10` 给的是 `7` 而不是 `3` ⟹ 拆出来的数位全错。

**解法（本专题统一用这个）**：
```python
sign = -1 if x < 0 else 1
x = abs(x)              # ! 之后所有 % 和 // 都作用在非负数上
...
return sign * result
```

**不要用 `int(x / 10)` 做向零截断** —— `x / 10` 是浮点，
大整数（超过 2^53）会丢精度。

📍 [LC-0007 Reverse Integer](<../03 - 整数运算与数位处理 (Arithmetic)/01 - 数位进位与整数反转/02 - LC-0007 - Reverse Integer>)

## 二、32-bit signed 范围

```python
INT_MIN = -(2**31)      # -2147483648
INT_MAX = 2**31 - 1     #  2147483647
```

**为什么 Python 不会自动出现 32-bit Overflow？**
Python 的 `int` 是**任意精度**的，底层是变长的 30-bit「数字」数组，
需要多少位就分配多少位。`9646324351` 在 Python 里是个完全合法的整数，
**不会**像 C++ 的 `int` 那样回绕成负数。

**但题目的输出限制依然要人工判断：**
```python
if res < INT_MIN or res > INT_MAX:
    return 0
```

> **C++ 里是「溢出会悄悄发生，所以要提前预判」；
> Python 里是「溢出不会发生，所以要事后判断」。
> 两种语言都要写检查，但原因正好相反。**

### C++ / Java 的预判写法（不允许 64-bit 时）

```cpp
// 累加之前判断，因为一旦溢出就来不及了
if (res > INT_MAX / 10 || (res == INT_MAX / 10 && digit > 7))  return 0;
if (res < INT_MIN / 10 || (res == INT_MIN / 10 && digit < -8)) return 0;
res = res * 10 + digit;
```
`INT_MAX / 10 == 214748364`；只有 `res` 恰好等于它时才比较末位
（`2147483647` 末位 **7**，`-2147483648` 末位 **8**）。

### 不对称：`|INT_MIN| > INT_MAX`

`-(-2147483648) = 2147483648` **超出 int 范围**。
所以 C++/Java 里 `-n`、`abs(n)` 在 `n == INT_MIN` 时都会溢出。

**受影响的题**：
- LC-0007：输入 `-2147483648`
- LC-0050 Pow(x, n)：指数 `n == -2^31` 时 `-n` 溢出
  ⟹ 必须先转 `long`，或单独处理这个值

**Python 完全不受影响** —— 但面试写 C++ 时必须主动提出来。

## 三、浮点数：能不用就不用

| 场景 | ❌ 浮点做法 | ✅ 整数做法 |
|---|---|---|
| 判两点连线的斜率相同 | `(y2-y1)/(x2-x1)` | **gcd 约简的方向向量** `(dx//g, dy//g)` |
| 判三点共线 | 比较两个斜率 | **叉积** `(y2-y1)*(x3-x1) == (y3-y1)*(x2-x1)` |
| 判两点距离相等 | `sqrt(...)` | 比较**距离的平方**（都是整数） |
| 向零截断 | `int(x / 10)` | `abs` + `//` |
| 二分取中点 | `(lo+hi)/2` | `lo + (hi-lo)//2` |

**为什么浮点斜率不行？**
两个问题：**除零**（垂直线）和**精度**
（数学上相同的斜率可能因为约简路径不同而得到不同的 float）。
面试里只要写了 float 斜率，面试官就会追问精度。

📍 [LC-0149 Max Points on a Line](<../04 - 坐标几何与空间计数 (Geometry)/03 - 斜率归一化与共线计数/01 - LC-0149 - Max Points on a Line>)

**什么时候浮点是可以的？**
LC-0050 Pow(x, n) 的输入输出本来就是 `float`，无法回避。
但快速幂只做 `O(log n)` 次乘法，误差累积远小于朴素的 `O(n)` 次连乘
⟹ **快速幂不仅更快，精度也更好**。
测试要写 `abs(got - want) < 1e-9`，别指望严格相等。

## 四、`gcd` 的两个坑

```python
from math import gcd
gcd(0, 0)   # == 0   ⟹ 用它做除数会 ZeroDivisionError！
gcd(-4, 6)  # == 2   ⟹ Python 3.5+ 的 math.gcd 只接受整数，返回非负
```

**规矩**：
1. 调 `gcd` 之前先排除 `dx == 0 and dy == 0`（重合点）。
2. 传 `abs()` 进去，符号单独处理。
3. 约简后**统一方向符号**，否则 `(1,2)` 和 `(-1,-2)` 会被当成两条不同的直线。

## 五、Leading Zeros（前导零）

| 场景 | 行为 |
|---|---|
| `int("021")` | `21` —— **自动吃掉前导零**，所以 LC-0007 的 `120 → 21` 天然正确 |
| LC-0043 Multiply Strings | 结果数组前面会有若干 0，**必须手动跳过**，但要留住 `"0"` 本身 |
| LC-0008 atoi | 输入的 `"  -0042"` 要正确解析成 `-42` |

LC-0043 的典型错误：`"0" * "0"` 把所有前导零都跳掉 ⟹ 返回**空字符串**而不是 `"0"`。

## 七、三条自检清单

**写数位题之前**：
1. 会有负数吗？→ 先剥符号
2. 有 32-bit 限制吗？→ 手写范围判断
3. 有前导零吗？→ 决定跳过还是保留

**写几何题之前**：
1. 能不能全程用整数？→ 能就绝不用浮点
2. 坐标会是负的吗？→ 检查 `min` / `max` / `abs` 的用法
3. 在数格子还是量长度？→ 决定要不要 `+1`

**写快速幂之前**：
1. 指数可能是负的吗？→ 取倒数
2. 指数可能是 `INT_MIN` 吗？→ C++/Java 要防 `-n` 溢出
3. `⊗` 满足结合律吗？→ 满足才能用这个模板（取模幂、矩阵幂都满足）
