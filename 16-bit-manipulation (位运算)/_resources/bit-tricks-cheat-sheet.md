# 位运算恒等式速查表（Bit Tricks Cheat Sheet）

> 位运算题几乎不需要「算法」，需要的是**一打恒等式**和**知道哪些在 Python 里会出事**。
> 这份表就是全部家当。

---

## 一、单位操作（Read / Set / Clear / Toggle）

| 操作 | 表达式 | 说明 |
|---|---|---|
| **读**第 `i` 位 | `x >> i & 1` | 返回 0 或 1 |
| **置 1** | `x \| (1 << i)` | OR 只会把 0 变 1 |
| **清 0** | `x & ~(1 << i)` | AND 只会把 1 变 0 |
| **翻转** | `x ^ (1 << i)` | XOR 翻转 |
| 测试第 `i` 位是否为 1 | `x & (1 << i) != 0` | 注意 `!= 0`，不要直接当 bool 比较值 |

**记忆法**：**OR 置一、AND 清零、XOR 翻转**。
这也是为什么 AND 单调递减、OR 单调递增 —— 见下面的「区间聚合」。

---

## 二、最低位 1（Lowest Set Bit）—— 最容易记混的两个

| 表达式 | 作用 | 用在哪 |
|---|---|---|
| `x & (x - 1)` | **清掉**最低位的 1 | Popcount（LC-0191）、判 2 的幂（LC-0231） |
| `x & (-x)` | **只保留**最低位的 1 | 分组区分位（LC-0260）、树状数组 lowbit |
| `x \| (x + 1)` | 把最低位的 0 置 1 | — |
| `x & (x + 1)` | 清掉末尾连续的 1 | — |

**验证**（`x = 0b1011000`）：
```
x          = 0b1011000
x & (x-1)  = 0b1010000     ← 清掉了第 3 位的 1
x & (-x)   = 0b0001000     ← 只剩第 3 位的 1
```

**`x & (-x)` 为什么对？** 补码 `-x == ~x + 1`：
`-x` 等于「`x` 最低位 1 右边保持、最低位 1 本身保持、更高位全部取反」
⟹ AND 之后高位全灭。∎

## 三、Popcount（数 1 的个数）

```python
# ① Brian Kernighan：循环次数 = 1 的个数
cnt = 0
while x:
    x &= x - 1          # ! 每次清掉一个最低位 1
    cnt += 1

# ② Python 内置（最快，面试要先说出 ① 再提它）
cnt = bin(x).count('1')
cnt = x.bit_count()     # ! Python 3.10+

# ③ Counting Bits DP（LC-0338：一次算出 0..n 的全部 popcount）
dp = [0] * (n + 1)
for i in range(1, n + 1):
    dp[i] = dp[i >> 1] + (i & 1)       # ! i 的 popcount = (i//2 的) + 最低位
    # 或者 dp[i] = dp[i & (i - 1)] + 1 # ! 清掉一个 1 之后的 popcount + 1
```

**①的复杂度是 O(popcount)，不是 O(32)** —— 这是它比逐位扫描好的地方。

## 四、判断 2 的幂 / 4 的幂

```python
is_power_of_two = x > 0 and x & (x - 1) == 0     # ! 必须有 x > 0！
```
**为什么？** 2 的幂的二进制恰好只有一个 1 ⟹ 清掉它就是 0。
⚠️ **`x > 0` 不能省**：`x = 0` 时 `0 & -1 == 0` 会误判为真；
负数在 Python 里也会出问题。

```python
is_power_of_four = x > 0 and x & (x - 1) == 0 and x & 0x55555555 != 0
```
`0x55555555 = 0b0101...01`：4 的幂的那个 1 只会落在**偶数位**上。

## 五、XOR 的四个性质（本专题四道题各用一个）

| 性质 | 表达式 | 用在哪 |
|---|---|---|
| **抵消性** | `x ^ x == 0`、`x ^ 0 == x` | LC-0136 Single Number、LC-0268 Missing Number |
| **自逆性** | `a ^ b == c ⟺ a == c ^ b` | LC-0421 Max XOR（配对查询） |
| **算术含义** | `a ^ b` = 无进位和、`(a & b) << 1` = 进位 | LC-0371 Sum of Two Integers |
| **区分位** | `a ^ b != 0` ⟹ 至少有一位能把两者分开 | LC-0260 Single Number III |

还有：**交换律、结合律** ⟹ XOR 一串数时顺序无关，可以乱序、可以分段。

## 六、区间聚合：AND / OR / XOR 的规律**完全不同**

| 运算 | `[4, 7]` 的结果 | 规律 | 单调性 |
|---|---|---|---|
| **Range AND** | `4` (`100`) | **公共高位前缀**，低位全 0 | AND 单调**递减** |
| **Range OR** | `7` (`111`) | 公共前缀 + 低位全 **1** | OR 单调**递增** |
| **Range XOR** | `0` | 前缀 XOR 的**周期性公式**，与前两者无关 | 两个方向都可能 |

> ⚠️ **不存在通用公式。** LC-0201 学到的是 AND 的规律，
> **绝不能**迁移到 OR / XOR。

**Range XOR 的公式**（`0..n` 的 XOR，供参考）：
```python
def xor_0_to_n(n):
    return [n, 1, n + 1, 0][n % 4]     # ! 周期 4
# 区间 [l, r] 的 XOR = xor_0_to_n(r) ^ xor_0_to_n(l - 1)
```

## 七、Bitmask 当集合用

| 操作 | 表达式 |
|---|---|
| 加入元素 `i` | `mask \| (1 << i)` |
| 移除元素 `i` | `mask & ~(1 << i)` |
| 翻转元素 `i` | `mask ^ (1 << i)` |
| 元素 `i` 在不在 | `mask >> i & 1` |
| 全集（`n` 个元素） | `(1 << n) - 1` |
| 补集 | `full ^ mask` |
| 并集 / 交集 / 差集 | `a \| b` / `a & b` / `a & ~b` |
| **是否不相交** | **`a & b == 0`** |
| 元素个数 | `bin(mask).count('1')` |
| 枚举所有子集 | `for mask in range(1 << n)` |
| 枚举 `mask` 的**所有子集** | `sub = mask; while True: ...; if sub==0: break; sub = (sub-1) & mask` |

📍 LC-0318（集合相交判定）、LC-0078（枚举全部子集）

## 八、固定宽度反转（LC-0190）

```python
def reverseBits(n):
    res = 0
    for _ in range(32):                 # ! 必须恰好 32 次 —— 宽度是题目给定的
        res = (res << 1) | (n & 1)      # ! 从 n 的低位取，往 res 的低位推
        n >>= 1
    return res
```
**为什么必须循环固定 32 次而不是 `while n`？**
若 `n = 1`，`while n` 只转 1 次 ⟹ 得 1，但正确答案是 `2^31`。
**前导零也是有效位** —— 固定宽度题目里，宽度本身是题意的一部分。

## 九、⚠️ Python 专属陷阱（本专题最重要的一节）

### ① 整数是**任意精度**的，负数是**无限位补码**

```
-1  ==  ...111111111111      （概念上无限多个 1）
```

**后果**：`(a & b) << 1` 这类**左移**操作在负数上会让高位无限生长
⟹ **循环永不终止**。

**正确做法**：手动模拟 32 位
```python
MASK, MAX_INT = 0xFFFFFFFF, 0x7FFFFFFF
...
value &= MASK                                 # ! 每轮都截断
return value if value <= MAX_INT else ~(value ^ MASK)   # ! 还原符号
```
📍 LC-0371 —— **不加 MASK 的代码在 `(-1, 1)` 上会挂死**，
该题的 `Solution_4_BROKEN` 保留了这个反面教材并用测试证明了它不收敛。

### ② `>>` 对负数是**算术右移**（符号位延伸）

```python
-8 >> 1    # == -4（不是 2147483644）
```
所以「逐位扫描负数」会扫出无限多个 1。要先 `& MASK`。

### ③ 哪些操作**不需要** MASK

| 操作 | 安全吗 | 为什么 |
|---|---|---|
| `x & (x - 1)` | ✅ `x > 0` 时安全 | 只清位，不生长 |
| `x & (-x)` | ✅ `x > 0` 时安全 | 结果只取决于低位 |
| `a ^ b`（只做 XOR，不左移） | ✅ 安全 | 不生长 |
| `(a & b) << 1` 并迭代 | ❌ **危险** | **左移让高位无限生长** |
| 逐位扫描负数 | ❌ **危险** | 无限多个符号位 |

> **判断标准：有没有 `<<`，以及有没有「扫完所有位」的循环。**
> 有 ⟹ 先 `& MASK`。

### ④ `bin(-5)` 给的是 `'-0b101'`，不是补码

```python
bin(-5)              # '-0b101'       ← 带负号，不是补码！
bin(-5 & 0xFFFFFFFF) # '0b11111111111111111111111111111011'   ← 这才是 32 位补码
```
所以 `bin(x).count('1')` 对负数是**错的**，必须先 `& MASK`。

## 十、必测边界

| # | 边界 | 为什么 |
|---|---|---|
| 1 | **0** | `x & (x-1) == 0` 会误判 0 为 2 的幂 |
| 2 | **1** | 固定宽度反转的试金石（`while n` 版会错） |
| 3 | **负数** | Python 的无限位补码 + 算术右移 |
| 4 | **`-2^31`**（最小值） | C++/Java 里 `-n` / `abs(n)` 会溢出 |
| 5 | **`2^31 - 1`**（最大值） | 符号位边界 |
| 6 | 只有**一个** 1 的数 | 2 的幂系列 |
| 7 | **全 1**（`0xFFFFFFFF`） | Popcount = 32 |
| 8 | 两个输入**相等** | XOR 变 0 |
| 9 | 两个输入只差**一个 bit** | 分组区分位（LC-0260） |
| 10 | 两个输入差**最高位** | 高位优先贪心（LC-0421） |
