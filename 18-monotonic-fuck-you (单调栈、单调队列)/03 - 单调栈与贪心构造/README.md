# Level 1 · 03 单调栈与贪心构造

## 核心定义
用单调栈**构造**一个字典序最优的结果：从左往右扫，
遇到更小的元素就把前面较大的元素弹掉 —— 前提是「弹掉它是安全的」。

## 决定性观察
1. 字典序是**逐位比较**的，所以越靠前的位置越值钱：
   只要能让更高位变小，后面全部变大也值得。
2. 所以 Pop 的收益条件永远是同一句：`stack[-1] > x`（严格大于才换，相等换了没收益）。
3. **三道题的唯一区别是「什么时候允许 Pop」这个可行性条件**，不是三套不同的算法：

| 题 | 约束 | 允许 Pop 的条件 |
|---|---|---|
| LC-0402 | 恰好删 k 个 | `k > 0`（删除预算还没花完） |
| LC-0316 | 每种字符恰好一次 | `last_occurrence[stack[-1]] > i`（弹掉的以后还能回来） |
| LC-1673 | 恰好保留 k 个 | `len(stack) + (n - i) > k`（后面还够补满） |

## Loop Invariant
栈里是「到目前为止能构造出的、字典序最优的前缀」，且（在约束允许的范围内）单调不减。

## 正确性（交换论证，三题通用）
设最优解在第 p 位放了 v，算法放了 u < v。算法敢放 u，说明可行性条件成立，
即「前 p-1 位相同 + 第 p 位放 u」仍能补成一个合法答案，
而它的字典序严格小于最优解 —— 矛盾，所以算法的选择就是最优的。

## 典型模板
```python
stack = []
for i, x in enumerate(nums):
    while stack and stack[-1] > x and <可行性条件>:
        stack.pop()
    stack.append(x)        # LC-0316 还要配 in_stack 集合去重
```

## 收尾（容易漏）
- LC-0402：预算没花完 → 从**末尾**继续删；去掉前导零；结果为空返回 `"0"`。
- LC-1673：栈可能超过 k → push 前判断 `len(stack) < k`，或者最后 `stack[:k]`。
- LC-0316：已经在栈里的字符**不能重复入栈**。

## 常见错误
- 用 `>=` 弹相等元素 → 白白消耗预算，结果不是最优（402 会多删）。
- LC-0316 忘了检查「以后还会不会再出现」→ 弹掉就再也回不来，答案缺字符。
- LC-0402 忘了处理 `num="10", k=2 → "0"` 和前导零 `num="10200", k=1 → "200"`。
