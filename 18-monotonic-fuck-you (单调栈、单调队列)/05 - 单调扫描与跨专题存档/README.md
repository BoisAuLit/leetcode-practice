# Level 1 · 05 单调扫描与跨专题存档

## 这个 Level 1 的用途
放那些**可以用单调性理解、但不一定需要标准单调栈 / 队列**的题，
以及 Primary Pattern 属于别的专题、只是来源在这里的存档。

> 重要原则：**不要为了算法分类，强行给一道题套上不必要的数据结构。**
> 这一章的三道题全都有比「单调栈」更简单、更诚实的解法。

## 题目

### 01 - Car Fleet 与到达时间单调扫描 → LC-0853 Car Fleet（P1）

**模式**：Sorting + Monotonic Arrival-time Scan。**不是** Next Greater Element。

决定性观察：
1. 车不能超车，所以**只能按位置排序**（按速度排序没有意义 —— 后面的慢车追不上也挡不住）。
2. 按位置**从大到小**（离终点最近的先处理），算每辆车独自到终点的时间
   `t = (target - position) / speed`。
3. 如果后车的 `t <= 前方车队的 t`，它会在终点或更早追上 → **合并**（相等也合并，
   因为在终点处相遇就算同一个车队）；否则它自己形成一个新车队。
4. 只需要和**当前最前方车队的到达时间**比较，不必和每辆车比：
   车队的速度由最慢的那辆（也就是时间最大的那辆）决定。

两种等价写法：用 Stack 存各车队的到达时间，或只维护 `last_fleet_time` + 计数器。
**栈不是必需的** —— 栈底永远不会被弹出，实际只用到了栈顶，所以一个变量就够。

复杂度：**O(n log n)**（排序主导），不能因为扫描是 O(n) 就说整体 O(n)。

原 NeetCode 来源已正式化为 LC-0853；用户手写图解 `asset-Scan 15.jpeg` 原样保留。

### 02 - Suffix Maximum 与右侧可见性 → LC-1762 Buildings With an Ocean View（P2）

**模式**：Suffix Maximum（后缀最大值）。**根本不需要单调栈**。

从右往左扫，维护 `max_height_to_right`；
`height > max_height_to_right` 时当前建筑有海景，然后更新最大值。

为什么是**严格大于**：右边只要有一栋**同样高**的楼，视线就被挡住了，
所以等高不算有海景。O(n) 时间、O(1) 额外空间（不算输出）。

放在本专题是因为它和「单调递减序列」是同一回事（答案序列本身就是单调递减的），
但标记 P2 —— 不要为它背一套 Stack 模板。

### 03 - Greedy 跨专题来源存档 → LC-0134 Gas Station（P2）

**Primary Pattern = Greedy + Running Balance。不是单调栈，也不是单调队列。**

- `total = Σ(gas[i] - cost[i]) < 0` → 无解，返回 -1。
- 一次扫描：`tank` 掉到负数时，说明从当前候选起点出发撑不到 i，
  且 `start..i` 之间任何一点作为起点也撑不到 i（否则 tank 不会在 i 处才变负），
  于是候选起点直接跳到 `i + 1`，`tank` 清零。
