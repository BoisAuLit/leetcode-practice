# Amortized O(n)（摊还分析）

## 问题
```python
for i in range(n):
    while stack and ...:
        stack.pop()
    stack.append(i)
```
里面有嵌套 while，为什么**不是** O(n²)？

## 答案
看的不是「单次迭代最多弹多少」，而是「**整个过程一共弹了多少次**」。

- 每个元素最多被 `append` 一次 ⇒ 总 push 次数 ≤ n。
- 一个元素被 pop 之后**不会再回到同一个栈** ⇒ 总 pop 次数 ≤ 总 push 次数 ≤ n。
- 所以 while 循环体在整个外层循环中总共只执行 O(n) 次。

平均到每次迭代就是 **摊还（Amortized）O(1)**，整体 O(n)。

## 但不能机械地给所有单调题写 O(n)

| 题 | 真实复杂度 | 原因 |
|---|---|---|
| LC-0496 / 0739 / 0084 / 0907 / 0239 | O(n) | 标准摊还 |
| LC-0503 | O(n) | 跑 2n 轮仍是常数倍；**只有前 n 轮入栈**，总 push 仍 ≤ n |
| LC-0901 单次 `next()` | 最坏 **O(n)**，n 次调用总计 O(n)，摊还 O(1) | 一次调用可能弹空整个栈 —— **不能说单次 O(1)** |
| LC-0853 Car Fleet | **O(n log n)** | 扫描 O(n)，但前面有一次排序，排序主导 |
| LC-0085 Maximal Rectangle | **O(rows × cols)** | 每行跑一次 O(cols) 的栈 |
| LC-0316 | O(n)，字符集 26 | 额外的 `in_stack` 集合与 `last_occurrence` 都是 O(1) 查询 |
| LC-1856 | O(n) | 前缀和 O(n) 预处理 + 一次栈扫描 |

## 空间
几乎都是 O(n)：构造一个严格递增（或递减）的输入，栈就会一直涨到 n。
LC-1762 是例外 —— 后缀最大值只需要 O(1) 额外空间。

## 面试时怎么说
> 「虽然有嵌套循环，但每个元素最多入栈一次、出栈一次，
> 所以总的栈操作次数是 O(n)，摊还下来每步 O(1)。
> 不过这道题前面有排序 / 外层还有 rows 层，所以整体是 O(…)。」

把「摊还」和「整体」分开说，比笼统地讲 O(n) 更准确。
