# FAQ —— 针对 questions_about_monotonic.md 的回答

原始笔记：[../questions_about_monotonic.md](<../questions_about_monotonic.md>)（原文未作任何修改）。
下面按原文提出的疑问逐条回应。

---

### Q：原笔记说「真正值得形成肌肉记忆的只有 6 道」，这个判断对吗？

**基本正确，本次重构把它微调成 7 道。**

原笔记的 6 道：`496 → 739 → 901 → 84 → 239 → 907`。
本专题的核心路线在此基础上**加了 LC-0402**，理由：
前 6 道全都是「分析型」单调栈（找边界、算答案），
而 402 代表的「**构造型**贪心单调栈」是一个独立的、面试高频的不变量族
（402 / 316 / 1673 都靠它），缺了它会有知识盲区。

---

### Q：原笔记的两个骨架（Stack 用 `resolve`，Deque 用「删掉不可能的候选」）准确吗？

**准确，而且这是整份笔记里最有价值的一句话。** 本专题把它扩成一张对照表，
见 [stack-vs-deque.md](<stack-vs-deque.md>)。

唯一要补充的是：原笔记的 Deque 骨架里
```python
while dq[0] 不在窗口内: dq.popleft()
```
只覆盖了 **LC-0239 的「过期」** 这一种情况。
**LC-0862 的队首弹出不是过期，而是「已结算」** —— 它根本没有固定窗口。
这两种 `popleft()` 的理由不同，不能混为一谈。

### Q：原笔记把 1475 列为「推荐」，本专题为什么没收？

1475（Final Prices）就是 Next Smaller，和 496 共用同一个模板，
只是把比较符号反过来。它不引入新的不变量，收益低于记忆成本，
所以记在根 README 的 **Future Candidates** 里，没有建实体目录。
如果想练手，直接把 Template 1 的 `<` 改成 `>` 即可。

### Q：原笔记把 42（Trapping Rain Water）列为「推荐」，它在哪？

### Q：原笔记的分类树（Next Greater / Previous / Boundary + Deque）和现在的目录对得上吗？

对得上，本次重构基本沿用了它，只做了两处扩充：

| 原笔记的分类 | 现在的 Level 1 / 2 |
|---|---|
| 1. Next Greater / Smaller | `01/01`（496、739、503） |
| 2. Previous Greater / Smaller | `01/02`（901） |
| 3. Boundary / Contribution | `02/01` 矩形（84、85）+ `02/02` 贡献（907、2104、1856） |
| Monotonic Deque | `04`（239 + 1438/862 索引） |
| *（原笔记没有）* | `01/03` 从右扫描（456）、`03` 贪心构造（402、316、1673）、`05` 单调扫描存档 |

**把「矩形」和「贡献计数」拆成两个 Level 2** 是有意的：
两者共享边界思想，但换算公式不同（面积要 `right-left-1`，个数要 `(i-left)*(right-i)`），
放在一起最容易写错。

### Q：为什么 907 被原笔记标成「必刷但偏难」？难在哪？

不难在单调栈，**难在重复元素的 Tie Breaking**。
如果两侧都用严格比较，`[1,1]` 会被算成 4 而不是 3。
把 [contribution-counting.md](<contribution-counting.md>) 里那条约定记住就行：
**一串相等的元素中，只有最左边那个有权认领整串。**

---

### Q：刷的顺序到底按哪个？

原笔记的 `496 → 739 → 901 → 84 → 239 → 907` 是**精简路线**，适合快速建立识别能力。
根 README 的阶段 A–G 是**完整路线**，适合系统过一遍。
两者不冲突：先按原笔记的 6 道建立直觉，再按阶段顺序补齐变体。
