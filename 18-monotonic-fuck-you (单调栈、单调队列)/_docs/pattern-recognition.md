# Monotonic Pattern Recognition Guide（题型识别）

> 先问「**我真正要解决什么**」，再决定要不要用单调结构。
> 题目标签里出现 Stack **不是**使用 Stack 的理由。

| # | 如果题目在问… | 就用 | 代表题 |
|---|---|---|---|
| Q1 | 右边第一个**更大**的元素 | Next Greater 单调（递减）栈 | 496、739、503 |
| Q2 | 右边第一个**更小**的元素 | Next Smaller 单调（递增）栈 | 1475、84 的右边界 |
| Q3 | 某元素向左右能延伸的**有效范围** | Previous / Next Boundary 栈 | 84、907、1856 |
| Q4 | 柱状图里的**最大矩形** | 递增栈 + `h × (right-left-1)` | 84、85 |
| Q5 | 一个元素是**多少个子数组**的 min / max | Contribution Counting | 907、2104 |
| Q6 | 不断删掉前面更大的数字 / 字符，求**字典序最优** | Greedy Monotonic Stack | 402、316、1673 |
| Q7 | **固定长度**窗口的最大值 | Monotonic Deque | 239 |
| Q8 | **变长**窗口同时要 max 和 min | 两个 Monotonic Deque | 1438 |
| Q9 | 含**负数**时满足前缀和约束的最短子数组 | Prefix Sum + Monotonic Deque | 862 |
| Q10 | 只需要从右往左维护最大值 | Suffix Maximum，**可能不用栈** | 1762 |
| Q11 | 车队追赶与合并 | 排序 + 到达时间单调扫描 | 853 |
| Q12 | Gas Station 的可行起点 | Greedy Running Balance，**不是单调栈** | 134 |
| Q13 | `i<j<k` 且值呈 **1-3-2** 形状 | 从右扫 + `third`（被弹出的最大值） | 456 |

## 三个反例（什么时候不要用单调栈）
- **LC-1762**：后缀最大值一个变量就够，用栈是过度设计。
- **LC-0134**：这是贪心的 running balance，和单调性无关。
- **LC-0853**：是排序 + 扫描；写成栈也行，但栈底永远不弹，等价于一个变量。

## 决策顺序
1. 我要的是「某个元素的答案」还是「某个窗口的答案」？
   → 元素 ⇒ Stack；窗口 ⇒ Deque。
2. 答案是在**别人到来时**被确定的，还是**我到来时**汇总过去？
   → 前者 739 型，后者 901 型。
3. 需要距离 / 宽度 / 区间和吗？→ 需要就**存下标**。
4. 有重复元素吗？→ 有就立刻去查 [严格 / 非严格速查](<strict-vs-nonstrict.md>)。
