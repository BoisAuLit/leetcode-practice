# Monotonic Stack vs Monotonic Deque

|  | Monotonic Stack | Monotonic Deque |
|---|---|---|
| 支持的操作 | `append` / `pop` / `peek` | `append` / `pop` / `popleft` |
| 核心问题 | 当前元素能否**确定某个旧元素的答案**？ | 谁**永远不可能**成为窗口里的最优解？ |
| 弹出的语义 | 被弹者**此刻拿到答案** | 被弹者**被淘汰，没有答案** |
| 需要 popleft 吗 | 一般不需要（栈底还没拿到答案） | 需要 |
| 典型不变量 | 栈里是「还欠着答案」的下标 | 队列里是「还有竞争力」的候选下标 |
| 代表题 | 496 739 503 901 84 85 907 2104 1856 402 316 1673 456 | 239 1438 862 |

## 队尾弹出：两者相同
都是**支配关系**：新元素又新又优 ⇒ 旧元素永远没机会 ⇒ 永久删除。

## 队首弹出：两种不同的原因（最容易混的地方）

**原因 A · 过期（Expiration）—— LC-0239**
```python
if dq[0] <= i - k:
    dq.popleft()        # 下标滑出窗口了，和它的值好不好无关
```

**原因 B · 已结算（Settled）—— LC-0862**
```python
while dq and prefix[i] - prefix[dq[0]] >= k:
    best = min(best, i - dq.popleft())   # 答案已记录；留着它只会得到更长的子数组
```

**不能把所有 `popleft()` 都解释成「窗口过期」。**
LC-0862 根本没有固定窗口，它的队首弹出是「这个起点的最优答案已经取到了」。

## 一个实用判据
- 元素一旦进入结构，**只会因为被解决或被支配而离开** ⇒ Stack。
- 元素还可能因为**时间 / 位置约束**而离开 ⇒ Deque。
